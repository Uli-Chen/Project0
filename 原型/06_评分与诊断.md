# 06 评分与诊断（⑤，也用于 ⑧）

**位置**：提交后的第一个评估步骤。上游：[05](05_提交与检查.md) 创建的快照与 `evaluations(queued)`。下游：分数与逐项观察交给 [07_反馈与回顾](07_反馈与回顾.md)；改写稿的结果交给 [09_对比](09_对比.md)；观察结果交给 [10_记忆整理](10_记忆整理.md)。

**目标**：对一篇作文给出四项分数，并对照分类表逐项判断每个问题是否出现。两个调用都**隔离**：只看题目、作文与固定规则。

## 1. 隔离原则

评分与诊断的输入只有：题目、按句编号的作文、评分要点或分类表、确定性特征。

不得输入：记忆、提纲、教练对话、任务重点、用户以前的分数、原稿分数（评估改写稿时）、模式（练习或模考）。

代码层面保证：这两个调用的输入组装函数只接收 `{prompt, essay, features}` 三个参数。

## 2. 确定性特征（代码计算）

```ts
features = {
  word_count, paragraph_count, sentence_count,
  avg_sentence_words,
  duration_sec,                     // 仅用于 B01，不传给模型
  connector_counts: { moreover: 3, however: 1, ... },   // 常见连接词出现次数
  repeated_connectors: ["moreover"]  // ≥3 次的
}
```

传给模型的特征不含 `duration_sec`。

## 3. 评分 `scoring`

### 3.1 评分要点

`prompts/scoring/rubric_v1.md`：依据雅思官方公开的 Task 2 四项评分描述，用自己的话整理每项 4～9 分各档的关键区别，不复制受版权保护的教材内容。字数明显不足、跑题等情况按官方描述处理。

### 3.2 输入与输出

输入：评分要点、题目、编号句子（`[1] ...`）、features。

输出 Schema：

```ts
{
  dims: Array<{
    dim: "TR" | "CC" | "LR" | "GRA";
    band: number;                 // 0–9，0.5 一档
    rationale: string;            // ≤80 字中文
    evidence: number[];           // 句子 id
  }>;                             // 恰好 4 项，各一次
  flags: Array<"off_topic" | "under_length" | "memorized" | "not_essay">;
}
```

### 3.3 代码处理

- 校验：4 个维度齐全不重复；band ∈ {0, 0.5, …, 9}；evidence 中的 id 都存在。
- `overall = roundBand(四项平均)`。
- 写入 `scores_json = {dims, overall, flags}`。

## 4. 诊断 `diagnosis`

### 4.1 输入与输出

输入：分类表中全部 T 类与 L 类的 `code / name / detect`、题目与题型、编号句子、features。

输出 Schema：

```ts
{
  observations: Array<{
    code: Code;                    // T01–T09、L01–L11 每个恰好一次
    result: "present" | "absent" | "unclear";
    sentence_ids: number[];        // present 时必填，≥1
    count: number;                 // L 类：出现处数；T 类：涉及的段落数
    note: string;                  // ≤40 字中文
  }>;
  has_conclusion: boolean;         // 用于 B01
}
```

`unclear` 用于无法判断的情况，例如：题型为 `adv_disadv` 或 `problem_solution`、本身不要求回应反方时，T06 为 unclear；文章太短、无法判断段落结构时，T08 为 unclear。

### 4.2 代码处理

- 校验：20 个编码齐全不重复；present 时 sentence_ids 非空且都存在。
- L 类按分类表 `detect` 中的数量门槛复核：`count` 低于门槛时改为 absent。例如 L01 门槛为 ≥2 处。
- 追加 B 类（代码判断）：
  - B01：`duration_sec > 2700` 或 `has_conclusion = false` → present；
  - B02：`word_count < 250` → present。
- 写入 `observations_json`。

## 5. 执行与失败

```text
evaluations: queued → running
  并行：scoring、diagnosis
  两者都成功 → step=feedback → 进入 07（原稿）或 09（改写稿）
  任一失败   → status=failed, step=失败的那一步, error_json
```

- 已成功的一步在重试时不重跑：判断依据是对应列（`scores_json` / `observations_json`）是否已有值。
- 重试：`POST /api/evaluations/{id}/retry`，仅 status=failed 时可用，每个评估最多手动重试 3 次。
- `model_info_json` 记录每一步的模型、提示词版本、耗时。

## 6. 等待页与查询

`GET /api/evaluations/{id}` 返回 `{status, step, scores?, issues?, review?, error?}`；前端每 2 秒轮询。

等待页按 step 显示进度：“正在评分与诊断……”→“正在整理反馈……”。超过 90 秒仍未完成时显示“比平时慢，请稍候”。失败时显示原因与“重试”按钮。

## 7. 评测脚本（M1 交付）

`scripts/eval_scoring.ts`：

- 读取 `data/private/scoring_samples/*.json`，每个样本 `{id, prompt_text, essay, reference: {overall, dims?}, source}`。
- 每篇调用 scoring N 次（参数，默认 1；稳定性测试用 3 或 5）。
- 输出 `data/private/reports/<日期>_<提示词版本>_<模型>.md`，内容包括：
  - 每篇的参考分、预测分、偏差；
  - 平均绝对误差、±0.5 与 ±1.0 命中率；
  - 各分段的平均偏差；
  - 重复评分时每篇的最大差与标准差；
  - 调用次数、总 token 与费用。
- 不写入应用数据库。

## 8. 边界情况

| 情况 | 处理 |
|---|---|
| flags 含 off_topic | 照常给分；07 的第一条问题必须是 T07 |
| flags 含 not_essay | 评估仍 succeeded，但 07 只显示提示“这篇看起来不是一篇完整的议论文”，不出问题列表 |
| 诊断中 present 的编码超过 10 个 | 正常保存；07 只取前三 |
| 模型拒绝回答 | 视为失败，可重试 |

## 9. 验收用例

| # | 操作 | 期望 |
|---|---|---|
| 1 | 检查 scoring 与 diagnosis 的实际请求内容 | 只有题目、作文、规则与特征；无记忆、提纲、对话、历史分数、模式 |
| 2 | 四项 6, 6, 6.5, 5.5 | overall = 6.0 |
| 3 | 四项 6, 6.5, 6.5, 6 | overall = 6.5 |
| 4 | 模拟模型返回缺一个维度 | 重试一次；仍失败则 status=failed, step=scoring |
| 5 | scoring 成功、diagnosis 失败后点重试 | 只重跑 diagnosis |
| 6 | L01 的 count=1 | 复核为 absent |
| 7 | 用时 46 分钟的作文 | B01 present |
| 8 | 运行评测脚本 | 生成报告，含 MAE、命中率、波动与费用 |
