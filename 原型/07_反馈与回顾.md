# 07 反馈与回顾（⑥）

**位置**：原稿评估的第二步。上游：[06](06_评分与诊断.md) 的分数与逐项观察。下游：问题列表进入 [08_深化改写](08_深化改写与再评分.md) 与 [09_对比](09_对比.md)；`focus_result` 进入 [11_计划](11_计划.md)；`one_line` 进入下一次的 CoachContext（[02](02_领取任务.md)）。

**目标**：从诊断结果中选出最值得改的三个问题，并对这次写作过程做回顾。

本步只针对原稿执行；改写稿不再选问题，直接进入对比。

## 1. 输入

| 数据 | 来源 | 模考 |
|---|---|---|
| 编号句子、题目 | essays、prompts | ✓ |
| scores、observations | 06 | ✓ |
| 任务（重点、success） | CoachContext.task | 模考检查点无重点 |
| 提纲 | sessions.outline_json | ✗ |
| 已采用建议与 AI 文字占比 | suggestions、essays.ai_word_count | ✗ |
| memory_digest | CoachContext | ✓ |
| 自述条目 | memory_items(kind=self_report) | 仅入门测试 |

## 2. 代码预处理

在调用模型前由代码算出：

```ts
pre = {
  candidates: observations.filter(o => o.result === "present" && o.code 为 T 或 L 类),
  recurring_codes: candidates 中同时出现在 memory_digest 的编码,
  improved_codes: memory_digest 中 status ∈ {recurring, observed_once, improving}、本次 result === "absent" 的编码,
  focus_auto: 任务主重点的观察结果：absent → "yes"；unclear → "partial"；present → 待模型判断（只能是 partial 或 no）,
  ai_ratio: ai_word_count / word_count,
}
```

## 3. 调用 `feedback_review`

输入：第 1 节数据与 `pre`。

输出 Schema：

```ts
{
  issues: Array<{
    code: Code;                 // 必须在 pre.candidates 中
    title: string;              // ≤20 字
    why: string;                // 为什么影响分数，≤60 字
    sentence_ids: number[];     // 必须是该编码 observation.sentence_ids 的子集，≥1
    hint_l1: string;            // L1：一个引导问题，≤60 字，不给答案
  }>;                           // 0–3 条，按对分数的影响从大到小
  review: {
    outline_coverage: Array<{ slot: SlotPath; status: "written" | "partly" | "missing"; sentence_ids: number[] }>;
    breakthrough: string | null;       // 只能基于 pre.improved_codes 或带句号的具体表现
    focus_result: { achieved: "yes" | "partial" | "no"; note: string } | null;
    self_report_contrast: string | null;   // 仅入门测试
    one_line: string;                  // ≤30 字，供下次开场引用
  };
}
```

### 3.1 选题规则

1. 只从 `candidates` 中选，最多 3 条，不足 3 条不凑数。
2. 按对分数的影响排序：一般 T 类优先于 L 类，除非 L 类问题数量多到明显拉低 LR 或 GRA。
3. `scores.flags` 含 `off_topic` 时，第一条必须是 T07。
4. 任务重点编码若在 candidates 中，必须入选（不一定排第一）。
5. 措辞针对本文，引用用户自己的句子；不说“你经常……”，除非该编码在 `recurring_codes` 中。

### 3.2 回顾规则

- `outline_coverage`：只列提纲中非空的槽位。
- `focus_result`：`pre.focus_auto` 为 yes 或 partial 时照抄；为待判断时，模型在 partial 与 no 中选择，并写一句理由。
- `self_report_contrast`：使用 [90](90_共享规范.md) 第 2.5 节的映射，比较自述对应的编码与本篇 present 的编码，一句话说明相符与不符之处，并引用句号。

## 4. 代码校验与合成

| 校验 | 不通过时 |
|---|---|
| issue.code 不在 candidates | 丢弃该条 |
| sentence_ids 不是该编码观察结果的子集 | 取交集；为空则丢弃该条 |
| 任务重点在 candidates 中却未入选 | 重试一次；仍缺失则由代码追加一条（title 用分类表 name，why 用 detect，hint_l1 用 prewrite 追问） |
| focus_result 与 focus_auto 冲突（例如 auto=yes 而模型给 no） | 以 focus_auto 为准 |
| outline_coverage 中的 sentence_ids 不存在 | 删除不存在的 id |

合成后写入：
- `issues_json`：每条加上 `rank`（1 起）与 `recurring: boolean`（code ∈ recurring_codes，由代码判断）；
- `review_json`：加上 `ai_ratio`（练习模式）；
- 评估 status=succeeded，`sessions.stage` → feedback；
- 有任务时，`plan_tasks.result_json = {achieved, note, evaluation_id}`。

## 5. 反馈页

| 区域 | 内容 |
|---|---|
| 分数 | overall 与四项；标注“AI 实验性预估”和模式（练习·有辅导／模考）；点开看每项 rationale |
| 原文 | 按段显示；问题涉及的句子按问题编号高亮 |
| 问题卡片 | 编号、title、why、`recurring` 时显示“上次也出现过”、L1 提示、按钮“和教练聊聊”（练习与模考均可用，进入 08） |
| 回顾（练习） | 提纲覆盖情况；本次重点是否做到；突破；AI 文字占比 |
| 回顾（模考） | 本次重点（如有）；突破 |
| 入门测试额外 | 见 [01](01_入门.md) 第 5 节 |
| 按钮 | “开始改写”（stage → revising）、“不改写，结束本次练习”（调用 finish，见 [10](10_记忆整理.md)） |

`POST /api/sessions/{id}/start-revision`：前置 stage=feedback；创建改写草稿，初始内容为原稿全文；stage → revising。

## 6. 边界情况

| 情况 | 处理 |
|---|---|
| candidates 为空 | issues 为空；页面显示“这篇没有发现需要优先改的问题”，仍可改写 |
| flags 含 not_essay | 不调用本步模型，issues 为空，review 只有 one_line（代码模板） |
| 本步失败 | 分数照常显示；问题区显示“反馈暂不可用”与重试；重试只重跑本步 |

## 7. 验收用例

| # | 情境 | 期望 |
|---|---|---|
| 1 | 诊断 present 5 个编码 | issues ≤3，均来自这 5 个 |
| 2 | 任务重点 T02 为 present，模型没选 | 重试或由代码追加，最终 issues 含 T02 |
| 3 | 任务重点 T02 为 absent | focus_result.achieved = yes |
| 4 | 记忆中 L01 为 recurring，本篇 L01 present | 对应问题卡片显示“上次也出现过” |
| 5 | 记忆中 T03 为 observed_once，本篇 T03 absent | breakthrough 可提到 T03 的改善 |
| 6 | 入门测试，自述“语法错误多”，本篇 L 类只有 L01，T02、T03 present | self_report_contrast 指出更突出的是 T 类问题，附句号 |
| 7 | 第一次使用（无记忆） | 所有措辞不出现“经常”“上次” |
| 8 | 模考 | 回顾无提纲覆盖与 AI 占比 |
