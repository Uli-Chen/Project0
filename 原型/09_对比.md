# 09 对比（⑨）

**位置**：改写稿评分与诊断之后（evaluation step=comparison）。上游：原稿与改写稿的 essays、两份评估（[06](06_评分与诊断.md)、[07](07_反馈与回顾.md)）、提纲。下游：对比结果进入 [10_记忆整理](10_记忆整理.md)（素材与观点保留）；页面上的“完成本次练习”触发结束流程。

**目标**：如实展示改写前后的变化：分数、文字、每个问题是否处理、用户的观点是否被保留并深化。

## 1. 句子对应（代码）

`mapSentences(original, revision)`：

1. 相似度：两句的词多重集合 Dice 系数 `2|A∩B| / (|A|+|B|)`，忽略大小写与标点。
2. 对每个原句取相似度最高的改写句：
   - ≥0.95 → `kept`；
   - [0.5, 0.95) → `edited`。
3. 未匹配的原句：
   - 若其 ≥70% 的词出现在某个已匹配的改写句中 → `merged`（指向该句）；
   - 若有两个及以上改写句，各自 ≥50% 的词来自该原句 → `split`（指向这些句）；
   - 否则 → `deleted`。
4. 没有被任何原句指向的改写句 → `new`。

结果存 `comparisons.sentence_map_json`：`{ original: [{id, type, revision_ids}], new_revision_ids: [] }`。单元测试覆盖保留、修改、合并、拆分、删除、新增六种情况。

## 2. 文本差异（代码）

用 `wordDiff` 按段落对齐显示：段落数相同时逐段比较；不同时整体比较。只用于展示。

## 3. 调用 `comparison`

输入：
- 题目；原稿与改写稿的编号句子；
- 原稿 issues（code、title、sentence_ids）；
- 句子对应表；
- 改写稿的 observations；
- 提纲（如有）；
- 两次分数（只用于说明，不得据此判断问题是否解决）。

输出 Schema：

```ts
{
  issues: Array<{
    rank: number;
    status: "resolved" | "partly" | "unresolved" | "removed";
    reason: string;                    // ≤50 字
    revision_sentence_ids: number[];
  }>;                                  // 每个原稿问题恰好一条
  idea: {
    stance_kept: boolean;
    kept_points: string[];             // 保留下来的用户观点，用用户原话概括
    deepened: Array<{ what: string; original_ids: number[]; revision_ids: number[] }>;
    changed: string[];                 // 观点发生改变的地方（不是错误，只是如实说明）
  };
  one_line: string;                    // ≤30 字，覆盖 07 的 one_line，供下次开场使用
}
```

### 3.1 状态定义

| 状态 | 含义 |
|---|---|
| resolved | 改写稿中对应位置已不再有该问题 |
| partly | 有改进，但问题仍部分存在 |
| unresolved | 没有改变或仍有同样问题 |
| removed | 原句被删除，且没有用新内容替代；不能视为学会 |

### 3.2 代码校验与校正

| 规则 | 处理 |
|---|---|
| 每个原稿问题恰好一条 | 缺失或重复时重试一次 |
| resolved / partly 必须给出 ≥1 个存在的改写句 id | 否则重试一次 |
| removed 要求该问题的所有原句在对应表中为 `deleted` | 否则校正：若改写稿诊断中该编码 present 且涉及对应句 → unresolved，否则 → partly |
| resolved，但改写稿诊断中该编码 present，且 sentence_ids 与 revision_sentence_ids 或对应句有交集 | 降为 partly |

校正记录在 `result_json.corrections`，供开发检查提示词。

## 4. 写入

- `comparisons`：sentence_map_json、`result_json = {issues, idea, one_line, corrections, score_delta}`；
- `score_delta`：四项与总分的差值；
- `version_mismatch`：两次评估的模型或提示词版本不同则为 true；
- 改写稿评估 status=succeeded；`sessions.stage` → compared。

## 5. 对比页

| 区域 | 内容 |
|---|---|
| 分数 | 原稿 → 改写稿的总分与四项，显示差值；可升、可平、可降，如实显示；固定说明“本次改写表现不等于能力已经稳定提升”；version_mismatch 时提示分差仅供参考 |
| 问题处理 | 每个问题：状态、理由；点击高亮原稿与改写稿的对应句 |
| 你的观点 | 是否保留立场；保留的观点；深化之处（附前后句对照）；有变化的地方 |
| 文字变化 | 删除线为删除，高亮为新增 |
| AI 文字占比 | 改写稿的占比 |
| 评价 | 可选：有没有用（1–5）、最终文章还是我的观点吗（是／部分／否）、一句话；`POST /api/sessions/{id}/rating` |
| 按钮 | “完成本次练习”（调用 finish，见 [10](10_记忆整理.md)） |

## 6. 边界情况

| 情况 | 处理 |
|---|---|
| 原稿没有问题 | issues 为空；只显示分数、观点与文字变化 |
| 改写几乎重写了全文（多数原句为 deleted） | 照常处理；问题状态主要依赖改写稿诊断 |
| 比较调用失败 | 分数与文字差异照常显示（不依赖模型）；问题与观点区显示重试 |

## 7. 验收用例

| # | 情境 | 期望 |
|---|---|---|
| 1 | 改写只改了一个词 | 对应句为 kept 或 edited；其余 kept |
| 2 | 把两句合并成一句 | 原句之一为 merged |
| 3 | 删除了问题句、没有替代 | 状态为 removed |
| 4 | 模型把一个仍存在 T02 的问题判为 resolved | 被代码降为 partly，记录在 corrections |
| 5 | 改写后分数下降 | 如实显示下降 |
| 6 | 用户改变了立场 | stance_kept=false，changed 中说明；页面不把它当作错误 |
| 7 | 比较调用失败 | 分数与文字差异仍可见；可重试 |
