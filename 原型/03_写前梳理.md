# 03 写前梳理（②）

**位置**：仅练习模式。上游：[02_领取任务](02_领取任务.md) 创建的会话（stage=prewriting）与开场白。下游：提纲进入 [04_写中协助](04_写中协助.md)，并在 [07](07_反馈与回顾.md) 的回顾中用于比对“提纲中哪些写进了文章”。

**目标**：通过一问一答，把用户自己的想法整理成一份每一点都能追溯到用户原话的提纲。

## 1. 提纲结构

```ts
type Slot = { text: string; sources: string[] } | null;   // sources：用户原话片段
type Outline = {
  stance: Slot;                                   // 立场
  reasons: Array<{ claim: Slot; why: Slot; example: Slot }>;   // 默认 2 个理由
  counter: { view: Slot; response: Slot };        // 反方观点与回应
  user_edited: boolean;
};
```

- 槽位顺序：stance → reasons[0].claim → why → example → reasons[1].claim → why → example → counter.view → counter.response。
- `null` 在界面显示为“还没想好”。
- `text` 用用户使用的语言（中文、英文或混合），由模型做最少的整理（去口头语、合并重复），不得添加新含义。

题型适配：
- `discuss_both`：counter 改为“另一方观点”，立场槽位改为“你更倾向哪一方”；
- `two_part`：reasons 改为两组 `{question, answer, why, example}`，分别对应题目两问。

## 2. 每一轮的处理

用户发送一条消息 → `POST /api/sessions/{id}/prewrite` → 返回教练回复与提纲更新。

### 2.1 调用 `prewrite_turn`

输入：

```text
<context> CoachContext（任务重点、prewrite 追问方向、相关记忆与素材、偏好） </context>
<prompt> 题目 </prompt>
<outline> 当前提纲 JSON </outline>
<dialogue> 本阶段全部对话 </dialogue>
<user_message> 本轮用户消息 </user_message>
```

输出 Schema：

```ts
{
  slot_updates: Array<{ slot: SlotPath; text: string; source_quotes: string[] }>;  // SlotPath 如 "reasons.0.why"
  message: string;          // 给用户的回复：≤120 字中文，以一个问题结尾
  move: "ask" | "direction" | "recall_idea" | "confirm" | "wrap_up";
  next_slot: SlotPath | null;
}
```

### 2.2 教练规则（写入提示词，并由行为用例检查）

1. 每轮只推进一个槽位，只问一个问题。
2. 从用户本轮消息中提取能填入槽位的内容；**没有就不填**。
3. **方向而非结论**（move=direction）：用户说“不知道”或连续两轮没有实质内容时，可以给 2～3 个思考方向，例如“可以从个人、家庭、社会三个层面想”，然后问用户对哪个有感触。不得说出某个方向下的具体论点。
4. 有与本题相关的个人素材时，可以提醒（move=recall_idea），例如“你在 10 月 23 日那篇里提到表姐的经历，这里能用吗？”，由用户决定是否使用。
5. 任务有重点时，在对应槽位多追问一次。例如重点 T02 时，每个 why 槽位至少追问一次“为什么”。
6. 用户用中文回答时用中文回应；用户全英文时可用英文回应。
7. 不评价立场对错；用户被追问后自己改变想法，正常更新槽位。

### 2.3 代码校验（模型输出返回后执行）

| 校验 | 不通过时 |
|---|---|
| 每个 `source_quotes` 都能在本阶段用户消息中找到（忽略大小写、空白与标点差异） | 丢弃该条 slot_update，记录日志 |
| `slot` 路径存在 | 丢弃该条 |
| `message` 长度 ≤200 字 | 截断前重试一次 |

通过后合并到 `sessions.outline_json`。模型输出中的 `text` 若包含 source_quotes 之外的新名词性内容，原型阶段不做自动检测，靠行为用例覆盖。

### 2.4 结束条件

| 条件 | 行为 |
|---|---|
| 所有槽位非空 | 教练 move=wrap_up：“提纲好了，你可以开始写了，或者先改改提纲。” |
| 用户点“提纲好了，开始写” | 直接进入写作，空槽位保持“还没想好” |
| 用户点“跳过写前” | 进入写作，outline 为空 |
| 教练已回复 12 轮 | 下一轮 move 强制为 wrap_up |

进入写作：`POST /api/sessions/{id}/start-writing`，stage → writing。

## 3. 提纲编辑

`PUT /api/sessions/{id}/outline`，请求为完整 Outline。用户可以直接修改任意槽位文字或清空；保存后 `user_edited=true`。用户手写的文字视为用户原话，`sources` 记为 `["(用户编辑)"]`。写作阶段仍可编辑。

## 4. 界面

- 左：题目与对话；右：提纲（槽位逐个填亮，空槽位显示“还没想好”）。
- 输入框提示“中英文都可以”。
- 按钮：“提纲好了，开始写”“跳过写前”。
- 每条用户消息与教练回复存 `coach_messages(stage=prewriting)`；提纲更新存在 `meta_json.slot_updates`，便于回放。

## 5. 边界情况

| 情况 | 处理 |
|---|---|
| 调用失败 | 显示“教练暂时没有回应”与重试；用户可继续编辑提纲或开始写作 |
| 用户输入与题目无关 | 教练简短回应后拉回题目 |
| 用户要求“直接给我几个论点” | 说明会给方向而不是论点，然后给方向（规则 3） |
| 用户输入很长（>1,000 字） | 正常处理；只提取与当前槽位相关的内容 |
| 刷新页面 | 从数据库恢复对话与提纲 |

## 6. 验收用例

全部列入教练行为用例（见[总览·质量检查](00_总览.md#质量检查)）。

| # | 输入情境 | 期望 |
|---|---|---|
| 1 | 用户：“反对，免费的话大家就不珍惜” | stance 填“反对”；reasons.0.claim 填“免费的话大家不珍惜”；回复追问具体表现 |
| 2 | 用户：“我不知道” | move=direction；给出层面而无具体论点 |
| 3 | 用户连续中英混合回答 | 槽位保留用户原话语言；回复为中文 |
| 4 | 记忆中有相关素材 | 某一轮出现 move=recall_idea，并说明来源日期 |
| 5 | 模型输出了用户未说过的 source_quote | 该更新被丢弃，提纲不变 |
| 6 | 任务重点为 T02 | 每个 why 槽位填写前至少追问一次 |
| 7 | 用户手动清空一个槽位 | 显示“还没想好”；之后教练可再追问该槽位 |
| 8 | 第 12 轮后用户继续发消息 | 教练回复 wrap_up |
