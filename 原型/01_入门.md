# 01 入门

> **部分已被取代（2026-11-01）**：第 2 节问卷与第 4 节问卷写入的记忆仍然有效。第 3 节入门测试、第 5 节入门结果页、“生成计划”及相关验收用例 4～7 已取消：不再有必做的入门测试，基线改为第一次合格的模考检查点，见 [12](12_题库与推荐.md) 第 6 节。问卷收集的考试日期与每周次数只用于显示每周节奏（RFC §1、§5）。第 1.1 节的使用者选择已被登录注册取代（见根目录 README）。

**位置**：每位使用者只经历一次。上游：首页选择或新建使用者。下游：[11_计划](11_计划.md) 生成首版计划，之后进入 [02_领取任务](02_领取任务.md)。

**目标**：在约 2 分钟问卷和一篇 40 分钟模考之内，得到这个人的档案、基线分数、初始记忆和第一版学习计划。

## 1. 流程

```text
选择/新建使用者
  └─ 无 profile？→ ① 问卷 → 保存 profile
                     └─ ② 入门测试：创建 assessment 会话（固定题、模考）
                           └─ 写作 → 提交 → 评分与诊断 → 反馈与回顾（含自述对照）
                                 └─ 用户点“完成” → 记忆整理（初始记忆）→ 计划生成 → 计划页
```

入门测试复用 [05](05_提交与检查.md)～[07](07_反馈与回顾.md) 与 [10](10_记忆整理.md)，本文只写入门特有的部分。

## 1.1 使用者

原型不做登录。没有 Cookie 时整页显示使用者选择；之后在顶栏右侧的使用者菜单中切换或新建（见 [91](91_前端布局.md) 第 4.1 节），选择后设置 Cookie `wm_uid`。

| 方法与路径 | 说明 |
|---|---|
| `GET /api/users` | 全部使用者（id、name） |
| `POST /api/users` | `{name}`，名字 1～20 字、不可重复；创建后自动选中 |
| `POST /api/users/select` | `{id}`，设置 Cookie |
| `PATCH /api/users/me/settings` | `{nudges_enabled}` |
| `DELETE /api/users/me` | 删除该使用者及其全部数据（底线第 4 条），需二次确认 |

## 2. 问卷

### 2.1 字段与校验

| 字段 | 控件 | 校验 | 必填 |
|---|---|---|---|
| target_score | 下拉 5.0～8.0，0.5 一档 | 在范围内 | 是 |
| exam_date | 日期选择 | 晚于今天、早于今天 + 52 周 | 与 prep_weeks 二选一 |
| prep_weeks | 数字 1～52 | 整数 | 与 exam_date 二选一 |
| self_level | 单选：未考过 / 5 左右 / 6 左右 / 6.5 以上 | — | 是 |
| sessions_per_week | 数字 1～7 | 整数 | 是 |
| minutes_per_session | 单选：30 / 45 / 60 / 90 | — | 是 |
| difficulties | 多选（[90](90_共享规范.md) 第 2.5 节五项） | 至少选 1 项 | 是 |
| language_pref | 单选：先中文想再写英文 / 尽量英文 | — | 是 |

`minutes_per_session < 45` 时显示提示：“一次完整练习约需 45～60 分钟，可以分两次完成同一篇。”只提示，不阻止。

### 2.2 接口

| 方法与路径 | 请求 | 响应 |
|---|---|---|
| `GET /api/profile` | — | profile 或 `null` |
| `PUT /api/profile` | 上表字段 | 保存后的 profile；首次保存时同时写入两条记忆（见第 4 节） |

修改已有 profile 时触发计划重算（[11_计划](11_计划.md) 第 6 节，trigger = profile）。

## 3. 入门测试

### 3.1 创建

| 方法与路径 | 前置条件 | 行为 |
|---|---|---|
| `POST /api/onboarding/assessment` | profile 已存在；该用户没有已完成的 assessment | 创建 `sessions(kind=assessment, mode=mock, stage=writing, prompt_id=is_placement 那题)`，并按 [02](02_领取任务.md) 第 4 节组装 CoachContext（task 为 null，memory_digest 与 ideas 为空）；若已有未完成的 assessment，返回它而不新建 |

### 3.2 写作与提交

与普通模考完全相同：无写前、无写中协助，计时提示 40 分钟。见 [05_提交与检查](05_提交与检查.md)。

### 3.3 稍后再做

问卷页提供“稍后再做入门测试”。此时：
- 不生成计划，首页唯一的任务卡片是“完成入门测试”；
- 允许自由练习与自由模考，其结果照常进入记忆；
- 用户完成入门测试时，以入门测试为基线生成计划。

## 4. 入门写入的记忆

| 时机 | 写入 | 规则 |
|---|---|---|
| 问卷首次保存 | 每个 difficulties 选项一条 `kind=self_report`，summary 为选项原文，source=questionnaire | 只记录自述，不当作事实 |
| 问卷首次保存 | 一条 `kind=preference`，summary 为语言偏好，source=questionnaire | 修改 profile 时更新这一条 |
| 入门测试结束 | 按 [10_记忆整理](10_记忆整理.md) 正常执行 | 只有一篇作文，T/L 类全部为 observed_once |

`profiles.baseline_eval_id` 在入门测试原稿评估成功后写入。

## 5. 入门结果页

即入门测试的反馈页（[07](07_反馈与回顾.md)），额外显示：

1. **基线**：“你的起点：写作 X（AI 实验性预估）；目标 Y，相差 Z。”
2. **自述对照**：一句话，由 07 的 `self_report_contrast` 字段提供，例如“你觉得最难的是语法；这篇里语法问题确实有，但更影响分数的是理由没有展开（第 5、9 句）。”
3. 入门测试可以改写，但改写不改变基线。
4. 主按钮“生成我的学习计划”：调用 `POST /api/sessions/{id}/finish`，完成后跳转计划页。

## 6. 边界情况

| 情况 | 处理 |
|---|---|
| 入门测试作文被输入检查拒绝 | 照常提示原因，用户修改后重新提交 |
| 入门测试评估失败 | 照常显示重试；未成功前不生成计划 |
| 用户想重做入门测试 | 原型不支持；可做自由模考，不改变基线 |
| 切换使用者到一个没有 profile 的人 | 跳转问卷 |

## 7. 验收用例

| # | 操作 | 期望 |
|---|---|---|
| 1 | 新建使用者 | 跳转问卷页 |
| 2 | 只填 exam_date 或只填 prep_weeks | 均可保存；两者都不填时提示 |
| 3 | 保存问卷，查看记忆页 | 出现与所选难点数量相同的“自述”条目和一条偏好 |
| 4 | 开始入门测试 | 题目为 is_placement 那题；没有教练面板 |
| 5 | 完成入门测试并点“生成我的学习计划” | profile 有 baseline_eval_id；记忆中 T/L 条目均为 observed_once；出现计划页 |
| 6 | 选择“稍后再做” | 首页只有“完成入门测试”任务；自由练习可用 |
| 7 | 修改 profile 的考试日期 | 计划重算，plan_changes 新增一条 trigger=profile |
