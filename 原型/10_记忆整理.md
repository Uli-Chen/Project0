# 10 记忆整理（⑩）

**位置**：每次练习结束时。上游：本次会话的观察结果（[06](06_评分与诊断.md)）、反馈与回顾（[07](07_反馈与回顾.md)）、对比（[09](09_对比.md)）、提纲与对话（[03](03_写前梳理.md)、[04](04_写中协助.md)）。下游：更新后的记忆被 [11_计划](11_计划.md) 立即使用，并在下一次 [02_领取任务](02_领取任务.md) 中进入 CoachContext。

**0.4 补充**：速刷（[13](13_速刷与主题卡片.md)）不经过本环节，不更新任何 T/L/B 记忆。主题卡片是“我的素材”在界面上的主要形式；本篇第 4 节的素材提取仍对精练生效。写作重点的统计只用“新原稿”（RFC §6；同一题目家族只有第一次提交的精练原稿算），关联重写与重复练习都不算。

**目标**：把本次练习合并进长期记忆。T/L/B 类由代码按规则更新，模型只负责从用户自己的话中提取素材。

## 1. 触发：结束练习

`POST /api/sessions/{id}/finish`

| 前置条件 | 说明 |
|---|---|
| stage ∈ {feedback, compared} | 不改写直接结束，或对比完成后结束 |
| 原稿评估 succeeded | 否则返回 409 |

也会被 [02](02_领取任务.md) 第 3 节自动调用（开始新练习时补做遗留会话）。

**幂等**：`sessions.finished_at` 已有值时直接返回上次的结果，不重复更新。

处理顺序（同一个请求内顺序执行；失败时不写 finished_at，可重试）：

1. 更新 T/L/B 类（第 3 节，纯代码）
2. 提取素材（第 4 节，模型）
3. 更新偏好（第 5 节，代码）
4. 生成“这次我记住了”（第 6 节，代码）
5. 写 `sessions.finished_at`，stage → finished；计划任务 status=done
6. 调用计划调整（[11](11_计划.md) 第 6 节，trigger=session，或模考检查点时 trigger=checkpoint）

响应：`{ memory_changes, plan_change_summary }`。前端显示结果后返回首页。

## 2. 用哪一篇的观察结果

- **只用原稿的 observations** 更新 T/L/B 类：每个会话计为一次“检查”。
- 改写稿的诊断只用于 09 判断问题是否解决，不计入记忆次数，因为改写稿是在问题被指出之后写的。
- 练习模式与模考模式的原稿同等计入，记忆事件中记录 mode，供以后分析。

## 3. T/L/B 类的状态规则 `updateMemoryStatus`

对 T01–T09、L01–L11、B01–B02 中的每个编码，取本次原稿的观察结果 r：

| r | 计数 |
|---|---|
| present | `checked += 1`；`seen += 1`；追加证据 `{session_id, essay_id, sentence_ids, quote}`（quote 取第一句原文，≤30 词），证据最多保留最近 5 条 |
| absent | `checked += 1` |
| unclear | 不变 |

条目不存在且 r=present 时新建（kind 按编码类别，summary 为分类表 name，source=assessment）；条目不存在且 r≠present 时不建。

状态由最近的检查历史计算（历史来自 `memory_events` 中该条目的 seen / not_seen 记录，按会话时间排序）：

```text
H = 该条目的检查结果序列（只含 present/absent），最新在后；规则按顺序匹配，命中即停
1. 条目刚新建                                              → observed_once
2. H 的最后两次都是 absent                                   → resolved
3. 最后一次是 absent，且当前为 recurring 或 observed_once      → improving
4. 最后一次是 present，且最近 3 次中 present ≥ 2              → recurring
5. 最后一次是 present，且当前为 resolved 或 improving          → recurring
6. 其他                                                     → 保持不变
```

每次变化写一条 `memory_events`（seen / not_seen / status_changed，含 from_status、to_status）。

用户删除过的条目（deleted_at 非空）：不再更新，也不重新创建同一编码，除非用户在记忆页“恢复”。

**单元测试**必须覆盖：
- 序列 P → observed_once；
- P,P → recurring；
- P,P,A → improving；
- P,P,A,A → resolved；
- P,P,A,A,P → recurring；
- P,A → improving；
- unclear 不计数。

## 4. 素材提取 `idea_extract`

输入：
- 题目与 topic_tags；
- 提纲（含 sources）；
- 本会话所有用户消息（写前、写中、问题对话）；
- 原稿与改写稿正文；
- 对比结果中的 `idea.kept_points` 与 `deepened`。

输出 Schema：

```ts
{
  ideas: Array<{
    summary: string;            // ≤40 字，用用户自己的表述
    stance: string | null;      // 对应的立场，如“反对大学免费”
    kind: "reason" | "example";
    source_quotes: string[];    // 用户原话片段，≥1
    topic_tags: string[];       // 从题目 topic_tags 中选
  }>;                           // 0–3 条，只取有具体内容、可在其他题目中复用的
}
```

规则：只提取用户自己表达过的内容，不提取教练提出的方向或示范句。

代码校验：
- 每个 source_quote 必须出现在用户消息、提纲（用户编辑或 sources）或用户正文中；不满足的条目丢弃；
- 与已有素材 summary 高度相似时（Dice ≥0.8）只更新 last_seen_session，不新建。

写入：`memory_items(kind=idea, source=coach_dialogue, evidence_json=[{session_id, quotes}])`。

## 5. 偏好（代码）

| 信号 | 写入 |
|---|---|
| 写前对话中用户消息以中文为主（中文字符占比 >50%） | preference：“先用中文梳理想法” |
| 主动提醒已关闭 | preference：“关闭了主动提醒” |
| 连续 2 次跳过写前 | preference：“倾向直接开始写” |

偏好每类最多一条，存在则更新。

## 6. “这次我记住了”

由本次的 `memory_events` 生成列表，代码模板：

| 事件 | 显示 |
|---|---|
| 新建 T/L/B 条目 | “新发现：{name}（第 x、y 句）” |
| → recurring | “{name} 又出现了，之后会重点练” |
| → improving | “{name} 这次没有出现，在改善” |
| → resolved | “{name} 已连续两次没有出现” |
| 新素材 | “记下了你的素材：{summary}” |

每条带“删除”“修改”按钮。

## 7. 记忆页

| 接口 | 说明 |
|---|---|
| `GET /api/memory` | 按 kind 分组返回未删除条目，含状态、次数、最近证据 |
| `PATCH /api/memory/{id}` | 修改 summary 或 topic_tags；user_edited=true |
| `DELETE /api/memory/{id}` | 写 deleted_at；之后不再被引用 |
| `POST /api/memory/{id}/restore` | 清除 deleted_at |

页面：思维习惯、语言问题、行为、我的素材、偏好、自述，六个分组；每条显示状态、出现次数/检查次数、最近一条证据原句与日期。

## 7.1 进展（首页与进展页）

`GET /api/progress` 返回：

| 字段 | 内容 |
|---|---|
| mock_scores | 所有模考模式原稿的 `{date, overall, dims}`，含入门测试，按时间排序 |
| practice_scores | 练习模式原稿与改写稿的 `{date, original, revision}` |
| issues | T/L/B 条目的状态分布，以及每条的 seen/checked |
| ideas | 素材数量，按 topic 分组 |
| plan | 计划任务完成数、跳过数、安排数 |

首页显示精简版：模考分数变化、“在改善的”（improving / resolved）前 2 条、“仍要注意的”（recurring）前 2 条、素材数量。进展页（`/progress`）显示完整数据。

衡量进展只看 mock_scores。practice_scores 标注“有辅导”，与模考分开显示，不画在同一条线上。

## 8. 边界情况

| 情况 | 处理 |
|---|---|
| 素材提取失败 | 跳过素材，其余照常完成；记录日志 |
| 计划调整失败 | 记忆已更新；finish 仍成功，计划页提示“计划暂未更新”，提供重试 `POST /api/plan/recompute` |
| 放弃的会话（abandon） | 不执行本流程 |
| 同一会话重复调用 finish | 返回上次结果 |

## 9. 验收用例

| # | 情境 | 期望 |
|---|---|---|
| 1 | 第一次练习 T02 present | 新建 T02，observed_once，证据含句号与原句 |
| 2 | 连续三次 T02 为 P, P, A | 状态 recurring → improving |
| 3 | 改写稿 T02 absent、原稿 present | 只按原稿计数 |
| 4 | 用户在写前说了表姐的例子 | 新增素材，source_quotes 来自用户原话 |
| 5 | 教练给的方向“可以从社会层面想” | 不作为素材 |
| 6 | 删除 L01 后再练一次，L01 present | 不重新创建，不在 CoachContext 中出现 |
| 7 | finish 调用两次 | 第二次不重复计数 |
| 8 | 查看“这次我记住了” | 与 memory_events 一致 |
