# 08 深化改写与再评分（⑦⑧）

**位置**：反馈之后。上游：[07](07_反馈与回顾.md) 的问题列表（stage=feedback / revising）。下游：改写稿经 [05](05_提交与检查.md) 提交，由 [06](06_评分与诊断.md) 独立评分与诊断，再交给 [09_对比](09_对比.md)。

**目标**：围绕每个问题，用逐级加深的提示帮用户自己想出改法；改写时写中协助照常可用；改写稿与原稿以同样的方式独立评估。

⑧ 改写评分完全复用 06，本文只说明差异（第 5 节）。

## 1. 问题对话的级别

| 级别 | 内容 | 何时出现 |
|---|---|---|
| L1 | 一个引导问题 | 反馈页默认显示（07 的 hint_l1） |
| L2 | 指出改的方向，例如“在这句后面补一句说明原因” | 用户点“再给点提示” |
| L3 | 用用户自己的内容示范一句，并说明为什么这样写 | 已经看过 L2 后，用户再点“再给点提示” |

- 级别只升不降，每个问题独立计算，最高 L3。
- 当前级别 = 该问题已显示过的最高级别，由服务端从 `coach_messages(stage=issue, issue_rank)` 计算，忽略客户端传来的级别。
- 不提供整段改写或范文。

## 2. 接口

`POST /api/sessions/{id}/issues/{rank}/hint`

```json
{ "action": "more" }                                   // 要更深一级的提示
{ "action": "attempt", "text": "Because ..." }        // 用户试写一句，请教练看看
{ "action": "ask", "text": "为什么这里算断言？" }     // 针对该问题提问
```

前置条件：stage ∈ {feedback, revising}；rank 存在于原稿评估的 issues 中。

响应：`{ level, message, demo_sentence?, check_result? }`

## 3. 调用 `issue_hint`

输入：
- CoachContext（重点、偏好）；
- 题目；原稿编号句子；
- 该问题（code、title、why、sentence_ids、对应句子原文）；
- 提纲中与这些句子相关的槽位；
- 该问题的对话历史；
- action、用户文本、目标级别。

输出 Schema：

```ts
{
  message: string;                  // ≤120 字中文，以问题或明确的动手指令结尾
  demo_sentence: string | null;     // 仅 L3，1 句英文
  check_result: "addressed" | "partly" | "not_yet" | null;   // 仅 attempt
}
```

### 3.1 规则

- **more**：按目标级别（当前级别 + 1，上限 3）给出内容。
- **attempt**：判断这一句是否解决了问题，给出 check_result 与一句理由，并提出下一步；不提高级别。
- **ask**：回答问题，不提高级别。
- **L3 示范句**必须使用用户在原句、提纲或本问题对话中已经表达的内容，只改变表达或补上缺失的逻辑连接；不引入新的论点或例子。
- 用户要求“直接帮我改好整段”时，说明原因，并给出当前级别允许的帮助。

### 3.2 代码校验

| 校验 | 不通过时 |
|---|---|
| L3：demo_sentence 与“用户内容集合”（原句、提纲槽位文字、本问题对话中用户消息）共享 ≥3 个实词（去掉停用词，忽略大小写与词尾 s/ed/ing） | 重试一次；仍不通过则不返回示范句，message 改为 L2 级别的方向，并记录日志 |
| demo_sentence 为单句 | 重试一次 |
| L1、L2 返回了 demo_sentence | 丢弃 demo_sentence |

每次请求与回复存入 `coach_messages(stage=issue, issue_rank, level, action)`；attempt 的 check_result 存在 `meta_json`。

## 4. 改写

- `POST /api/sessions/{id}/start-revision`（见 [07](07_反馈与回顾.md) 第 5 节）后进入 revising。
- 改写页布局：左侧为只读原稿（问题句高亮，问题卡片可展开并继续对话）；右侧为改写编辑器，初始为原稿全文。
- 写中协助全部可用（[04](04_写中协助.md)，`essay_kind=revision`）；主动提醒对改写稿同样生效，按改写稿的段落序号独立计算。
- 计时从进入 revising 开始重新计，只作记录，不提示 40 分钟。
- 每个会话只有一份改写稿。

## 5. 改写稿的评估（⑧）

提交走 [05](05_提交与检查.md)（essay_kind=revision），评估走 [06](06_评分与诊断.md)，差异如下：

| 项目 | 原稿 | 改写稿 |
|---|---|---|
| 评分输入 | 题目、作文、规则、特征 | 相同；**不提供原稿分数、问题、对话** |
| 诊断 | 执行 | 执行（供 09 判断问题是否解决） |
| 第二步 | feedback_review（07） | comparison（09） |
| 阶段 | evaluating → feedback | re_evaluating → compared |

两次评估使用 `config/models.ts` 中同一配置。若中途修改了评分模型或提示词版本，对比页提示“两次评分使用了不同版本，分差仅供参考”（比较两份 `model_info_json`）。

## 6. 边界情况

| 情况 | 处理 |
|---|---|
| 用户不改写，直接结束 | 07 的“不改写，结束本次练习” |
| 改写稿评估失败 | 与原稿相同的重试方式 |
| 用户在改写中离开 | 草稿保存；下次进入首页时提示继续（[02](02_领取任务.md) 第 3 节） |
| 已到 L3 再点“再给点提示” | 返回提示“已经是最详细的提示了，试着自己写一句，我帮你看看” |

## 7. 验收用例

| # | 操作 | 期望 |
|---|---|---|
| 1 | 对问题 1 连点三次“再给点提示” | 依次返回 L2、L3、已达上限提示；级别从服务端计算 |
| 2 | 伪造请求要求直接到 L3 | 服务端按当前级别 + 1 处理 |
| 3 | L3 示范句 | 包含用户原句或提纲中的 ≥3 个实词；为单句 |
| 4 | attempt 一句解决了问题的句子 | check_result=addressed；级别不变 |
| 5 | 要求“帮我把这段改好” | 不给整段 |
| 6 | 提交改写稿，检查评分请求 | 无原稿分数、问题与对话 |
| 7 | 改写稿评估成功 | 进入对比；stage=compared |
