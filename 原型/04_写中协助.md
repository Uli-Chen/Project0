# 04 写中协助（③）

**位置**：练习模式的写作与改写阶段（stage=writing / revising）。上游：[03](03_写前梳理.md) 的提纲与 CoachContext。下游：草稿与建议采用记录进入 [05_提交与检查](05_提交与检查.md)；建议记录用于 AI 文字占比；对话进入记忆整理的素材提取（[10](10_记忆整理.md)）。

**目标**：在用户写作时随时响应，并在合适时机给出一句思路提醒；所有改动由用户决定是否采用。

模考模式下本环节全部关闭：不显示教练面板，接口返回 `409 stage_conflict`。

## 1. 编辑器

| 项目 | 规则 |
|---|---|
| 计时 | 进入 writing 时开始；`elapsed_sec` 随草稿保存；页面隐藏时不暂停（与考场一致）；超过 2,400 秒显示“已超过 40 分钟”，不强制提交 |
| 词数 | 前端用与 `countWords` 相同的规则实时显示 |
| 自动保存 | 每 5 秒（内容有变化时）及页面隐藏、关闭前调用 `PUT /api/sessions/{id}/draft`，请求 `{essay_kind, text, elapsed_sec}`；显示“已保存 hh:mm:ss” |
| 恢复 | 进入页面时 `GET /api/sessions/{id}` 返回草稿、提纲、对话与待处理建议 |
| 粘贴 | 允许，不检测 |

## 2. 用户发起的动作

选中正文中的一段文字后出现四个按钮；面板中另有自由输入框。

| action | 选中内容 | 调用 | 返回 |
|---|---|---|---|
| `clarify` 理清这段 | 一段或几句 | `writing_assist` | 一条文字回复：指出论点、理由、例子之间哪里断了，并提一个问题 |
| `express` 英文怎么说 | 无需选中；用户在面板输入想表达的意思（多为中文） | `writing_assist` | 1～2 张建议卡片（不同表达）＋区别说明 |
| `polish` 润色这句 | 一句（最多 2 句） | `writing_assist` | 1 张建议卡片 |
| `check` 检查这段 | 一段 | `writing_assist` | 最多 2 个问题，每个可附 1 张建议卡片 |
| 自由提问 | 可选 | `writing_chat`（流式） | 文字回复 |

接口：`POST /api/sessions/{id}/assist`

```json
{ "essay_kind": "original", "action": "polish", "selection": { "text": "...", "start": 120, "end": 168 }, "message": null }
```

自由提问：`POST /api/sessions/{id}/chat`，请求 `{essay_kind, message, selection?}`，响应为文本流。

### 2.1 `writing_assist` 的输入与输出

输入：CoachContext、提纲、当前全文、选中文字及其所在段落、用户消息。

输出 Schema：

```ts
{
  reply: string;                         // ≤120 字中文
  cards: Array<{
    type: "polish" | "express";
    original: string;                    // polish：选中原文；express：用户的中文意思
    suggested: string;                   // 英文
    reason: string;                      // ≤40 字中文
  }>;
  problems: Array<{ code: Code; excerpt: string; explanation: string }>;   // 仅 check
}
```

### 2.2 规则

1. **最小修改**：polish 只改必要的词，保留句意与用户的用词习惯；不添加用户没有表达的信息。
2. **不代写**：不生成整段或多句的新内容。express 每张卡片 ≤1 句。
3. **check 优先级**：本次任务的重点编码优先；其次是对分数影响大的问题；最多 2 个。不针对拼写逐个挑错，除非任务重点是 L10。
4. 自由提问中用户要求写一段或一篇时，说明原因并引导先写一句，然后可以对那一句提供帮助。

### 2.3 代码校验

| 校验 | 不通过时 |
|---|---|
| polish：`wordDiff(original, suggested)` 中新增词数 ≤ 原句词数的 50%，且 ≥1 | 重试一次；仍不通过则不返回卡片，只返回 reply |
| polish：`original` 与选中文字一致（忽略首尾空白） | 用选中文字覆盖 |
| express：`suggested` 为单句（`splitSentences` 结果为 1） | 重试一次 |
| check：`code` 在分类表中，`excerpt` 是选中文字的子串 | 丢弃该条 |

## 3. 建议卡片

- 每张卡片存一行 `suggestions(status=pending)`；`added_runs_json` 在创建时计算：`wordDiff(original, suggested)` 中所有新增的连续词片段，例如 `["value their education less"]`。express 的 `original` 为中文，整句 `suggested` 都算新增。
- 卡片显示原文与建议的对照（删除线、高亮）与原因。
- **采用**：`POST /api/suggestions/{id}/accept`
  - polish：前端把选区替换为 `suggested`；若选区文字已被用户改动，提示“原文已变化”，改为复制到剪贴板；
  - express：插入到光标处；
  - 服务端只记录状态与时间，正文以前端保存的草稿为准。
- **忽略**：`POST /api/suggestions/{id}/dismiss`。

## 4. 主动提醒

### 4.1 触发（前端）

同时满足才发送请求：
1. `users.settings_json.nudges_enabled = true`；
2. 用户在段落末尾输入换行，形成新段落后，停顿 8 秒没有输入；
3. 该段落（按段落序号）在本会话中还没被判断过；
4. 段落词数 ≥ 30。

### 4.2 判断（服务端）

`POST /api/sessions/{id}/nudge`，请求 `{essay_kind, paragraph_index, paragraph_text}`。

- 同一 `(essay_kind, paragraph_index)` 只判断一次，重复请求返回第一次的结果。
- 第一段（引言）只检查 T01、T07。
- 调用 `nudge`。输入：提纲、任务重点与 coach_hints.nudge、该段文字、题目。
- 输出 Schema：`{ should_nudge: boolean; code: Code | null; message: string | null }`，message ≤40 字中文。
- 只允许 T 类编码；返回 L 类时视为不提醒。

### 4.3 展示

- 面板顶部出现一句提醒，带“知道了”。
- 不弹窗，不打断输入。
- 面板底部有“主动提醒”开关，修改 `PATCH /api/users/me/settings`，跨会话记住。
- 提醒存 `coach_messages(role=coach, action=nudge, meta_json={paragraph_index, code})`。

## 5. 改写阶段的差异

stage=revising 时，本环节全部动作可用，`essay_kind=revision`。另外，问题卡片的分级提示见 [08](08_深化改写与再评分.md)。

## 6. AI 文字占比

在提交时（[05](05_提交与检查.md)）计算，结果写入 `essays.ai_word_count`：

```text
对本会话中 status=accepted、且 essay_kind ≤ 当前稿件（改写稿也计入原稿阶段采用的建议）的每张卡片：
  对 added_runs 中的每个片段：
    若片段（忽略大小写与多余空白）仍出现在最终正文中 → 计入该片段的词数
ai_word_count = 计入词数之和（不超过全文词数）
AI 文字占比 = ai_word_count / word_count
```

这是近似算法：用户从对话中手动抄写的文字不计入；同一片段在正文中多次出现只计一次。

## 7. 边界情况

| 情况 | 处理 |
|---|---|
| assist 调用失败 | 面板显示“没有获取到建议”与重试；不影响写作 |
| 选中文字超过 300 词 | 提示“请选择一段以内的文字” |
| 用户在建议返回前改了选区 | 采用时按第 3 节处理 |
| 主动提醒请求失败 | 静默失败，不重试 |
| 自动保存失败 | 显示“未能保存”，下次定时重试；连续 3 次失败时提示复制正文 |

## 8. 验收用例

| # | 操作 | 期望 |
|---|---|---|
| 1 | 选中 *Free education will make students not cherish.* 点润色 | 卡片建议只改少数词；附原因；新增词 ≤50% |
| 2 | 点采用 | 正文替换；suggestions.status=accepted；added_runs 只含新增片段 |
| 3 | 采用后用户又把建议中的词改掉，然后提交 | 被改掉的片段不计入 ai_word_count |
| 4 | 面板输入“我想说没付出代价就不觉得浪费” | 1～2 张 express 卡片，各为一句英文 |
| 5 | 检查一段含 5 个冠词错误的文字，任务重点为 T02 | 若该段存在 T02 优先指出；问题 ≤2 个 |
| 6 | 自由提问“帮我写第二段” | 拒绝代写并引导先写一句 |
| 7 | 写完一段无例子的论证段并停顿 8 秒，重点为 T03 | 出现一句提醒；同一段不再提醒 |
| 8 | 关闭主动提醒后新建会话 | 不再出现提醒 |
| 9 | 模考模式调用 assist | 返回 409 |
| 10 | 写作中刷新页面 | 正文、计时、对话、待处理卡片恢复 |
