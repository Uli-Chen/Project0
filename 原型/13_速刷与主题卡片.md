# 13 速刷与主题卡片：实现指南

**定位**：[RFC](../docs/designs/question_bank_first_practice.md) §4（卡片、来源、写成作文）与 §8（额度与恢复）的实现指南。**行为规则只以 RFC 为准**；本篇规定接口、动作、数据结构、模型调用格式、文件位置与测试对应。冲突时以 RFC 为准，并回来修改本篇。

**不做**：不打分；不更新思维（T）、语言（L）问题记忆；不进入评分与诊断（06）；不调用记忆整理（10）。

## 1. 流程（界面层面）

```text
开始速刷 → 学生直接在卡片上写（布局来自本题的要求，12 第 2.2 节）
        → 请教练看看（最多 2 次）→ 学生在对话框回答 → 学生自己改卡片，或把自己回答里的一段原话放进卡片
        → 检查（初检 1 次 + 主动复检 1 次，共享 1 次技术重试）
             ├ 通过 → passed，写完成事件，计一次速刷
             └ 还需展开 → needs_development，标出缺口
        → 任意时刻：先存着 / 搁置 / 写成作文
```

## 2. 卡片内容结构

```ts
type Provenance =
  | { kind: "direct"; userId: string; editId: string; editedAt: string; contentVersion: number }
  | { kind: "excerpt"; userId: string; messageId: string; start: number; end: number };

type Part = {
  key: string;                 // 例如 "q1.answer"、"viewA.why"
  text: string;                // 1～600 字
  provenance: Provenance;
  afterFollowUp: 0 | 1 | 2;    // 写入时已经发生过几次追问（只记上下文，不代表独立作者身份，RFC §4）
};

type CardContent = { layout: QuestionRequirements["layout"]; parts: Part[] };
```

- 每种 `layout` 的槽位清单写在 `lib/quick/layouts.ts`；槽位要对应本题 `subquestions`（例如原因与对策题有原因、对策两组）。不再使用“两个理由 + 反方”的通用模板。
- `excerpt` 的文字由服务端从**该用户自己**的、`role = user` 的消息原文中按 `start`、`end` 截取；客户端只传位置。编辑一段摘取的文字后，这段的来源改为 `direct`（RFC §4）。
- 模型输出不得写入任何 `Part`（G-11）。

## 3. 表

只写进 `lib/db/schema.ts` 并生成追加迁移；`lib/db/initialize.ts` 不加新表（与 12 第 3 节相同）。

| 表 | 主要列 | 删除练习时 |
|---|---|---|
| `topic_cards` | `id`、`user_id`、`attempt_id`（唯一 `(user_id, attempt_id)`，外键到 `writing_sessions` 级联）、`question_id`、`question_version`、`content_version`（只增）、`content_json`、`state`（`draft` / `needs_development` / `passed` / `unchecked`）、`last_check_id`、`last_checked_version`、`created_at`、`updated_at` | 删除 |
| `quick_check_results` | `check_id`（PK）、`user_id`、`attempt_id`（外键级联）、`card_version`、`outcome`、`results_json`（每条要求的结果与缺口说明）、`created_at` | 删除（含模型写的缺口说明） |

| `quick_operation_inputs` | `operation_id`（PK）、`user_id`、`attempt_id`（外键到 `writing_sessions` 级联）、`input_json`（冻结的题目要求、卡片版本快照、相关对话、配置版本） | 删除（含正文） |
| `request_receipts` | PK `(user_id, request_key)`；`attempt_id`、`action`、`params_hash`、`result_ref`（操作 ID 或子练习 ID）、`created_at`；同一请求键参数不同时返回 409 | 保留（无正文） |
| `llm_calls` | 见 90 第 4.1 节；速刷调用另带 `operation_id`、`package_id`、`reserved_input`、`reserved_output`、`reserved_ms` | 保留 |

## 4. 动作接口

走现有 `POST /api/sessions/{id}/actions`，但**不沿用**它“持锁等完整个模型调用、事后统一 `persist(session)`”的做法（`app/api/sessions/[id]/actions/route.ts:19-29`；`lib/pipeline/lock.ts` 遇到并发直接拒绝）。速刷动作按以下方式处理：

- **不调模型的动作**（`cardSave`、`cardExcerpt`、`quickAnswer`、`continueDeep`）：在一个同步短事务 `commitQuickMutation` 里重读会话与卡片、校验所有者与版本、修改卡片与会话 JSON、`version + 1`、写 `request_receipts`。事务之后不再由路由调用 `persist`。
- **调模型的动作**（`quickFollowup`、`quickCheck`、`quickRetry`）分三段：① 加锁，短事务里写 `quick_operations(running)`、`quick_operation_inputs` 与额度预留，解锁；② 不持锁调用模型；③ 再加锁，短事务里重读最新状态并提交（13 第 6 节第 5 步）。这样检查进行中，学生仍能保存新版本，检查结果会按 `stale` 处理。
- 运行状态读 `quick_operations`，不能用“锁是否存在”来判断。
- `completedRequests` 继续写入，供现有客户端兼容；真正的去重依据是 `request_receipts` 与 `quick_operations` 的唯一键。
- 会话已被删除时，提交阶段不得用现有的 upsert 保存函数把会话重新建出来。
- 新增 `GET /api/sessions/{id}/quick` 返回 `{ session, card, operations, budget }`，用于刷新恢复。

会话 `activity` 不是 `quick` 时这些动作返回 `409 unsupported_session`。所有动作的响应统一为 `{ session, card, operations, budget }`，其中 `budget` 是剩余额度和下次可申请复检的时间。速刷页面使用自己的客户端状态控制器，不复用现有 `SessionProvider` 的“忙碌”判断。

| 动作 | 请求 | 处理 |
|---|---|---|
| `cardSave` | `{ cardVersion, parts: Array<{key, text}> }` | 版本不等于当前 `content_version` 时返回 `409 card_conflict`；改动的 part 写 `direct` 来源；`content_version + 1`；`passed` 改为 `unchecked` |
| `cardExcerpt` | `{ cardVersion, key, messageId, start, end }` | 校验消息属于本会话、本用户、`role = user`、位置合法；写入原文 |
| `quickAnswer` | `{ text }` | 学生回答追问，存为对话消息，不进卡片 |
| `quickFollowup` | `{ cardVersion }` | 见第 5 节 |
| `quickCheck` | `{ cardVersion }` | 见第 6 节 |
| `quickRetry` | `{ operationId }` | 用同一快照重跑失败的操作，消耗共享重试额度 |
| `quickSupplemental` | `{}` | 申请补充检查包（RFC §8），条件不满足时返回原因与可申请时间 |
| `continueDeep` | `{ explicitNew: boolean, idempotencyKey }` | 见第 7 节 |

## 5. 追问 `quick_followup`

- 额度：先在一个短事务里**持久化预留**本次调用（次数、输入上限、输出 512、时长 25 秒，且不超过包内与用户 24 小时剩余额度，RFC §8），再在事务外调用模型，返回后再用短事务核销实际用量。**预留写入失败就不调用模型**；核销失败时保留预留。每一次自动重试都重新预留，并消耗包内共享的那一次重试额度。
- 输入：题目、本题 `subquestions`、当前卡片、本次已有的追问与学生回答；整个请求不超过 4,000 tokens，超出时返回提示、不截断。
- 输出 Schema：`{ question: string /* ≤80 字，以问号结尾 */, targetKey: string | null }`。
- 规则（提示词 + 行为用例 16、17）：只问一个问题；不给论点、例子或结论；可以给思考方向；不评价立场。

## 6. 检查 `quick_check`

1. 取卡片版本 v 的不可变快照。同一版本已有实质结果（通过或还需展开）时直接返回该结果，不消耗额度（RFC §8）。
2. 代码从本题 `subquestions` 和 `layout` 生成要求清单：`{ id, zh, keys[] }`。槽位为空的要求直接判为缺，不送模型；全部为空时不调用模型，也不消耗检查次数。
3. 预留额度（输出 768）→ 事务外调用模型 → 输出 Schema：

   ```ts
   { results: Array<{ id: string; status: "met" | "gap"; note: string | null /* gap 时 ≤60 字 */ }> }
   ```

4. 校验：覆盖每条送出的要求且没有多余的；`note` 不超过 60 字，且不含 6 个以上连续英文单词（防止写出示范句）。不合格时，若共享重试额度还在就自动重试一次，否则记 `invalid_output`。
5. 提交：在一个短事务里，**只有当前 `content_version` 仍等于 v、练习和账户都还在时**才写入卡片状态、`quick_check_results`、`last_check_id`，以及第一次通过时的 `completion_events`。否则这次操作记为 `stale`，不改卡片（RFC §4）。
6. 规则：只看是否回答了题目的每个要求、有没有相关的理由；不看观点好坏，不打分。

## 7. 写成作文（RFC §4）

- `continueDeep { explicitNew: false }`：查 `default_continuations`。已有子练习就返回它（“打开作文”）；已删除或已放弃时返回 `409 default_child_gone`，界面提示需要明确选择“另开一次练习”；没有就在事务里创建 `activity=deep, mode=practice` 的新会话，写入 `continuedFromQuickId` 和卡片快照（`cardSnapshot`：内容、来源、检查状态、版本），并写映射。
- `continueDeep { explicitNew: true }`：按 `idempotencyKey` 去重，创建另一次练习，复制当前卡片快照，不改映射。
- 精练会话的写前与写作阶段，左栏显示 `cardSnapshot`（只读）。之后改动原卡片不影响这份快照。

## 8. 恢复

- 服务启动时，把 `quick_operations.status = running` 的记录改为 `indeterminate`，预留额度保持扣除，不自动重发（RFC §8）。界面显示“上次检查没有完成”，提供使用重试额度的按钮；重试读取 `quick_operation_inputs` 中冻结的输入，不用当前卡片代替。
- 刷新或重复点击：同一 `(kind, card_version)` 已在运行时返回运行状态，不新建操作。

## 9. 复习页（`/cards`）

按主题分组；默认显示 `passed` 卡片的已检查版本；可切换显示草稿与未复查的卡片；每张卡片能打开原题与练习历史。

## 11. 测试对应

RFC §10 中与卡片、额度、恢复相关的行（“Passed card edited”“Directly typed card; selected user excerpt”“Quick Sunday, continued Deep Monday”“Budget exhaustion, crash…”“Later edited card after initial checks used”“Delete a Quick with consumed quota…”）都要有自动测试；另外：

| # | 情境 | 期望 |
|---|---|---|
| 1 | 检查版本 3 时另一个标签页保存了版本 4，随后检查返回“通过” | 结果记为 `stale`；卡片仍是版本 4 的 draft |
| 2 | 字段全空时检查 | 不调用模型、不扣检查次数，所有要求判为缺 |
| 3 | 摘取教练消息或别的用户的消息 | 拒绝 |
| 4 | 检查的 `note` 里有一整句英文示范 | 判为不合格并按规则重试 |
| 5 | 原因与对策题只写了对策 | 判为缺（来自本题 `subquestions`，不是来自题型） |
| 6 | 同一版本重复点检查 | 返回已有结果，不扣额度 |
| 7 | 速刷完成后看记忆页 | T/L 问题记忆不变 |
