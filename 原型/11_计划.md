# 11 计划生成与调整（⑪）

> **已被取代（2026-11-01）**：整篇不再实现。练习入口与推荐见 [12_题库与推荐](12_题库与推荐.md)；每周节奏只作显示（12 第 7 节）。本篇保留作历史参考。现有代码中练习结束时生成“下次计划”文字的部分（`lib/pipeline/engine.ts` 的 `finish` 动作中的 `planChange`）在 N0 删除。

**位置**：入门测试结束时首次生成；之后每次练习结束、模考检查点结束、问卷修改时调整。上游：profile（[01](01_入门.md)）、记忆（[10](10_记忆整理.md)）、任务结果（[07](07_反馈与回顾.md) 的 focus_result）。下游：`plan_tasks` 被 [02_领取任务](02_领取任务.md) 领取。

**目标**：规则决定节奏与重点，模型只负责把指令和理由写得贴合个人、并在候选题目中选一题。同样的输入一定得到同样的节奏与重点。

## 1. 参数（代码）

`buildPlanFrame(profile, today, history)` 计算：

| 参数 | 计算 |
|---|---|
| start_date | 首次生成计划的日期；之后不变（问卷修改也不变） |
| W0 | 首次生成时的剩余周数 |
| W | 剩余周数：有 exam_date 时为 `ceil((exam_date − today) / 7)`；否则为 `prep_weeks − 自 profile 保存以来经过的整周数`；最小为 0 |
| current_week | `floor((today − start_date) / 7) + 1` |
| S | sessions_per_week |
| baseline | 入门测试原稿 overall |
| latest_mock | 最近一次模考模式原稿的 overall（包括入门测试） |
| gap | target_score − latest_mock |

W = 0 时不生成任务，计划页显示“考试日期已过或准备期已结束，请更新信息”。

## 2. 阶段

阶段以“剩余的周”为单位，从 current_week 开始向后排：

| 剩余周数 W | 阶段划分 |
|---|---|
| W ≥ 6 | 补弱点：前 `ceil(0.33W)` 周；冲刺：最后 `max(1, floor(0.25W))` 周；强化：中间 |
| 3 ≤ W < 6 | 强化：前 W − 1 周；冲刺：最后 1 周 |
| W < 3 | 全部冲刺 |

存入 `plans.phases_json`：`[{phase, from_week, to_week}]`。

## 3. 每周的任务结构

只为 **current_week 与下一周** 生成具体任务；更远的周只显示阶段与“每周 S 次”。

| 阶段 | 任务构成（共 S 项，按此顺序） |
|---|---|
| 补弱点 / 强化 | focus_practice × (S − r − c)，rewrite × r，mock_checkpoint × c |
| 冲刺 | focus_practice × (S − r − m)，rewrite × r，mock_checkpoint × m |

- c（检查点）：第 2、4、6…周（相对 start_date）为 1，其余为 0。
- r（重写）：S ≥ 3 时为 1，否则为 0。
- m（冲刺期模考）：`ceil(S / 2)`。
- S = 1 时，检查点周的唯一任务是 mock_checkpoint。
- 任一类数量算出为负时取 0，优先保证 mock_checkpoint。

## 4. 重点排序 `rankFocus`

候选：T 类与 L 类、未删除、status ∈ {recurring, observed_once, improving} 的记忆条目。

```text
priority(code) = freq × recency × status_w × dim_w × phase_w × practiced_w

freq        = seen / max(checked, 1)
recency     = 1.0（最近一次结束的会话中出现）/ 0.7（最近 3 次内出现）/ 0.4（更早）
status_w    = recurring 1.0 / observed_once 0.8 / improving 0.6
dim_w       = 1.5 若该编码的任一 dims 是最近一次原稿评分中最低的维度（并列都算），否则 1.0
phase_w     = 补弱点：T 1.3、L 0.8；强化与冲刺：1.0
practiced_w = 0.5 若最近 2 项已完成任务中，它作为主重点且 achieved=yes
              0 若它已连续 3 项任务作为主重点（强制换一个，避免单调）
              否则 1.0
```

按 priority 降序排列，相同时按编码顺序（T01…T09, L01…L11）。

**分配到任务**（窗口内的第 k 个 focus_practice，k 从 0 开始）：
- 主重点：`ranked[floor(k / 2) mod len(ranked)]`，即每个重点连续练两次；
- 次重点：主重点为 T 类时，取排名最高的 L 类；为 L 类时，取排名最高的 T 类；没有则为空。

由于每次练习结束都会重算，实际起作用的是第一项待办任务，后面的任务是预览。

- **rewrite**：主重点为 ranked[0]；source_essay 取该用户最近一篇该编码为 present 的原稿；找不到时依次尝试 ranked[1]、ranked[2]；仍找不到则改为 focus_practice。
- **mock_checkpoint**：无重点。
- **无候选**（记忆为空或全部 resolved）：按最近一次原稿的最低维度取默认编码（[90](90_共享规范.md) 第 2.4 节）。
- **B 类附加**：B01 或 B02 的状态 ∈ {recurring, observed_once, improving} 时，把分类表中的附加句加入所有任务的 `coach_hints.extra`。

## 5. 选题（代码筛选，模型选择）

为每项任务生成 ≤5 个候选题目：

1. 排除 is_placement；
2. 排除该用户做过的题目，以及窗口内其他任务已分配的题目；
3. 排除最近 2 个会话或相邻任务使用过的 topic；
4. 题型须与主重点适配（[90](90_共享规范.md) 第 3 节）；
5. 候选不足时，依次放宽第 3 条、第 2 条（允许重复最早做过的题）。

mock_checkpoint 由代码从候选中随机选一题。

## 6. 调整的触发与范围

| trigger | 时机 | 做什么 |
|---|---|---|
| onboarding | 入门测试 finish | 首次生成：计算全部参数、阶段、窗口任务 |
| session | 每次 finish（非检查点） | 重新排序重点，重建窗口内的 todo 任务 |
| checkpoint | 模考检查点 finish | 同 session，另外执行进度比较（第 8 节） |
| profile | 修改问卷 | 重算 W、S、阶段与窗口任务；start_date 不变 |

重建窗口的步骤：

1. current_week 之前仍为 todo 的任务改为 skipped（`result_json = {reason: "expired"}`）；
2. 删除窗口内所有 todo 任务（done、skipped、in_progress 保留并计入本周数量）；
3. 按第 3～5 节补足本周与下周的任务；
4. 调用 `plan_wording` 生成文字（第 7 节）；
5. `plans.version += 1`；写一条 `plan_changes`。

`plan_changes.summary` 由代码按模板生成，比较重建前后的第一项待办任务与记忆状态变化，例如：
- “下一项重点由‘理由停在断言’改为‘例子缺失或空泛’：前者已连续两次没有出现。”
- “继续练‘理由停在断言’，换一个话题。”
- “考试日期提前到 11 月 30 日，剩余 4 周，已调整为强化＋冲刺。”

## 7. 调用 `plan_wording`

输入（每项 focus_practice / rewrite 任务一组）：分类表条目（name、instruction、success）、主重点与次重点的记忆证据（summary、最近一条 quote、日期）、候选题目、语言偏好。

输出 Schema：

```ts
{
  tasks: Array<{
    task_key: string;
    instruction: string;   // ≤60 字；保留模板中的核心动作，可结合这个人的证据具体化
    reason: string;        // ≤50 字；必须引用一条证据（日期或句子）
    prompt_id: string;     // 必须是候选之一
  }>;
}
```

- `success` 不经模型改写，直接使用分类表模板，保证 07 的判断标准稳定。
- 校验：prompt_id 不在候选中时取第一个候选；instruction 或 reason 为空时使用模板：instruction = 分类表 instruction，reason = “{日期}的练习中出现：{quote}”。
- 调用失败时全部使用模板，计划照常生成。

## 8. 如实提示

### 8.1 可行性提示（每次生成或调整时计算）

| 条件（满足任一） | warning |
|---|---|
| gap ≥ 2.0 | high |
| gap ≥ 1.5 且 W < 4 | high |
| gap ≥ 1.0 且 W < 2 | high |

high 时计划页顶部显示：

> “目标比目前模考成绩高 {gap} 分，剩余 {W} 周，难度较大。可以考虑：每周增加到 {S+1} 次／调整目标／保持不变。”

（S = 7 时不显示第一个选项。）选项只是建议，用户通过“修改我的信息”自行调整。

### 8.2 检查点进度（trigger=checkpoint）

```text
elapsed  = current_week − 1
expected = (target − baseline) × elapsed / W0      // 线性预期
actual   = latest_mock − baseline
elapsed ≥ 2 且 actual < expected − 0.5  → 落后
actual ≥ expected                      → 符合或领先
其他                                    → 基本符合
```

结果写入 plan_changes，计划页显示一句话。落后时附 8.1 中的三个选项，并说明“单篇模考成绩有波动，需要结合下一次检查点判断”。

### 8.3 不承诺

计划页与任何计划文字中不出现“保证”“一定能达到”“预计考到”等表述；“预计”只用于练习安排。

## 9. 接口

| 方法与路径 | 说明 |
|---|---|
| `GET /api/plan` | 参数、阶段、warning、各周（窗口内为任务列表，其余为摘要）、最近 5 条 plan_changes |
| `GET /api/plan/next` | 第一项待办任务（[02](02_领取任务.md)） |
| `GET /api/plan/changes` | 全部计划变化记录 |
| `POST /api/plan/recompute` | 手动重算（trigger=session），用于失败后重试 |
| `POST /api/plan/tasks/{id}/skip`、`/swap-prompt` | 见 [02](02_领取任务.md) |
