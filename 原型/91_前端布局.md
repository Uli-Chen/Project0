# 91 前端布局与视觉规范

各环节文档的“界面”一节写本环节显示什么；本文写这些内容放在哪里、为什么这样放，以及全站共用的视觉规范。两者冲突时以本文为准，并同步修改环节文档。

## 1. 核心模型：作文，而不是会话

用户关心的对象是“我写的那篇作文”，不是“一次练习流程”。因此：

- **一篇作文 = 一个页面**（`/essays/[id]`），从写前到对比都在这一页完成，结束后仍然能打开、重看反馈和对比。
- **原稿与改写稿是同一篇作文的两个版本**，在页面顶部切换，不是两个阶段。
- 后端的 `stage`（写前、写作、评估中、反馈、改写、再评估、对比、结束）保留为内部工作流状态，只用来决定“当前能做什么”和“默认打开哪个面板”，不再以向导或进度条的形式出现在界面上。数据模型不变：一条 session 记录就是一篇作文，`drafts.original` / `drafts.revision` 就是两个版本。

## 2. 布局原则

| 原则 | 做法 | 原因 |
|---|---|---|
| 对象优先 | 一级导航只有“作文”和“进展”；作文库是首页 | 用户回来时首先要找到自己的作文，其次才是统计 |
| 一个工作台 | 作文页的骨架固定：左提纲、中正文、右检查面板；阶段变化只改变面板内容和顶栏主按钮 | 不搬家，不需要每个阶段重新找东西 |
| 面板驱动正文 | 右侧检查面板的标签（教练／反馈／对比）决定中间正文的显示方式（可编辑／问题高亮／修订痕迹） | 同一份文字，换一种看法，而不是换一个页面 |
| 一个视图一个主操作 | 每个视图只有一个实心按钮；作文页的主按钮固定在顶栏右侧 | 用户永远知道“下一步”在哪 |
| 反馈附着在文字上 | 问题直接标在句子上，点问题定位句子，点句子定位问题 | 像老师批改，而不是读一份报告 |
| 不靠说明文字 | 不放标语、副标题、复述界面的提示；只保留不可撤销操作的后果、提交缺什么、看不见的功能入口 | 界面本身应当说清楚怎么用 |

## 3. 全站外壳

| 区域 | 页面 | 结构 |
|---|---|---|
| 应用外壳 | `/`、`/topics/[topic]`、`/essays`、`/cards`、`/progress`、`/account`、`/onboarding` | 左侧边栏（240px，可收起为 48px 图标栏）+ 内容区。侧边栏：品牌、练习、作文、卡片、进展；底部为账户菜单（账户设置、外观、退出） |
| 作文页 | `/essays/[id]` | 没有侧边栏，全宽工作台；顶栏左侧“作文 /”面包屑返回作文库 |
| 登录注册 | `/login`、`/register` | 居中的单张表单 |

旧路径重定向：`/sessions/[id]` → `/essays/[id]`；`/plan`、`/memory` → `/progress`。

只做桌面端：以 1280px 为基准，1440px 更宽松。低于 1280px 时作文页两侧栏变为抽屉（见 4.5）。

## 4. 作文页

### 4.1 顶栏（48px）

| 位置 | 内容 |
|---|---|
| 左 | “作文 /” 面包屑；题目（衬线、单行截断，点击弹出全文与“至少 250 词”）；类型标签（练习／模考／入门测试） |
| 中 | 版本切换：原稿 · 改写稿（有改写稿时出现；评估后各自带分数） |
| 右 | 写作中：用时、词数、保存状态；左右栏开关；更多菜单（下载、主动提醒开关、不改写直接结束）；**主按钮** |

主按钮随状态变化：

| 状态 | 主按钮 |
|---|---|
| 写前 | 开始写作 |
| 写作 | 提交评估（弹出确认：提交后不能再修改本稿） |
| 评估中 | 评估中…（禁用，显示已等待秒数） |
| 反馈（练习） | 开始改写；更多菜单里有“不改写，完成” |
| 反馈（模考检查点） | 完成；改写放在更多菜单（0.4 起无入门测试） |
| 改写 | 提交改写稿 |
| 对比 | 完成 |
| 已完成 | 无；可在更多菜单下载 |

### 4.2 三栏

| 栏 | 宽度 | 内容 |
|---|---|---|
| 左：提纲 | 260px，可收起 | 立场、理由、反方；写前逐个填亮，写作中可编辑，评估后逐项标出“已写进／部分／没写到”。模考与跳过写前且提纲为空时不显示 |
| 中：正文 | 自适应，纸面最宽 720px | 写前：大字题目。写作／改写：编辑器。其余：当前版本的只读正文，按右侧面板显示问题高亮或修订痕迹 |
| 右：检查面板 | 380px，可收起 | 标签：教练、反馈、对比（按可用性出现） |

模考写作时只有中栏，顶栏用时更醒目；提交后右侧出现反馈面板。

### 4.3 检查面板

| 标签 | 何时出现 | 内容 | 中栏随之显示 |
|---|---|---|---|
| 教练 | 练习的写前、写作；所有作文的反馈之后 | 本次重点；主动提醒；一条对话；输入框上方是上下文标签（引用的原文、针对的问题）和意图切换（提问／英文怎么说，有问题上下文时多一个“试写”） | 写作中：编辑器。其他阶段：只读正文 |
| 反馈 | 原稿评估后 | 分数与四项、评分依据（折叠）；问题列表（悬停高亮、点击定位句子、“讨论”切到教练并带上问题）；回顾；完成后的本篇小结 | 原稿 + 问题高亮 |
| 对比 | 改写稿评估后 | 前后分数；每个问题的处理情况；观点是否保留；AI 文字占比；评价 | 改写稿相对原稿的修订痕迹 |

默认标签：写前／写作／改写 → 教练；反馈 → 反馈；对比、已完成 → 对比（无改写稿时为反馈）。

意图规则（取代按语言猜测）：用户明确选择“提问”或“试写”。正文里选中文字点“问教练”时，自动切到“提问”并带上引用，移除问题上下文。

### 4.4 写前

左栏是逐步填亮的提纲，中栏是大字题目，右栏是教练对话。提纲有了立场后，对话末尾出现次要的“开始写作”；顶栏主按钮始终可用（跳过写前）。

### 4.5 窄窗口（< 1280px）

左右栏变为抽屉，由顶栏按钮打开。需要用户看到另一栏的操作会自动打开对应抽屉：选中文字求助 → 教练；点问题定位 → 正文。写前和反馈阶段首次进入时默认打开右侧抽屉，因为那时主要内容在右栏。

## 5. 首页、主题页、作文库与卡片（0.4）

0.4 起首页从作文库改为主题入口；作文库移到 `/essays`。一级导航：练习（`/`）、作文（`/essays`）、卡片（`/cards`）、进展（`/progress`）。显示什么见 [12](12_题库与推荐.md) 第 4、5 节和 [13](13_速刷与主题卡片.md) 第 7 节，本节只定位置。

### 5.1 首页（`/`）

| 区域 | 内容 |
|---|---|
| 标题行 | “练习” |
| 提示条（最多一条） | 未设置目标 → 设置目标；否则“继续”上次未完成的练习 |
| 检查点卡片 | 只在可以做或暂无可用题目时出现，位于提示条下方 |
| 主题列表 | 每行：主题名、已练 N 题、卡片 M 张、上次日期或“还没练过”；整行可点进主题页 |
| 右侧栏（≥1280px） | 本周：速刷 a · 精练 b / 目标 S，附预计用时；目标分；“上次的主题”快捷入口 |

### 5.2 主题页（`/topics/[topic]`）

| 区域 | 内容 |
|---|---|
| 标题行 | 主题名，“练习 /”面包屑 |
| 推荐卡片 | 题目（衬线，两行截断）、活动标签（速刷／精练）、一句理由；唯一的实心按钮“开始” |
| 题目表 | 题目、题型、卡片标记、精练标记、“继续”；整行点开题目详情（抽屉）：全文、尝试记录、“速刷”“精练”两个按钮 |

### 5.3 速刷页（`/essays/[id]`，`activity=quick`）

沿用作文页骨架：左栏为对话（追问与回答），中间为卡片（按题型的字段，可直接编辑），右栏为检查结果（每条要求的满足／缺口）。顶栏主按钮：检查；更多菜单：请教练看看（剩余次数）、先存着、搁置、申请补充检查（显示下次可申请时间）。通过后主按钮变为“用这张卡写成作文”；已有默认作文时变为“打开作文”。额度用完或检查未完成时，在右栏说明原因，不只显示错误提示。

### 5.4 作文库（`/essays`）

原首页的作文表格，筛选增加“速刷／精练”。新建作文对话框保留“粘贴题目”入口；“推荐”与“话题”入口删除，改由主题页提供。

### 5.5 卡片（`/cards`）

按主题分组；每组先列理由与例子，再列卡片；可切换显示草稿。

## 6. 进展（`/progress`）

一页包含原来的计划、记忆、进展：

| 区域 | 内容 |
|---|---|
| 目标 | 目标分、距考试周数、每周次数、本周进度；“调整”进入目标设置 |
| 成绩 | 模考成绩折线（总分／四项）；改写前后哑铃图；每张图可展开数据表 |
| 常见问题 | 来自作文反馈的问题，出现次数；可移除、恢复（移除后不再用于推荐重点） |
| 偏好 | 思考语言、自述难点；链接到目标设置 |

所有分数旁固定显示“AI 实验性预估，非官方成绩”。

## 7. 视觉规范

方向：科技产品的克制与精确（单色、细线、网格、等宽数字），加上写作的人文感（纸面、衬线、暖色中性）。避免：渐变、玻璃拟态、彩色大卡片、装饰插画、emoji、过多圆角与阴影。

### 7.1 字体

| 用途 | 字体 |
|---|---|
| 界面 | Geist Sans；中文回落到苹方 |
| 数字、元数据、快捷键 | Geist Mono（等宽数字） |
| 题目、正文、引用、例句 | Newsreader（衬线，可变字体）；中文回落到宋体 |

字体本地托管。界面基准 14px；页面标题 22px／600，字距 -0.02em；正文衬线 18px、行高 1.75，每行约 70 个字符。

### 7.2 颜色

| 名称 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| 背景 | `#faf9f7` | `#0c0c0b` | 应用底色，带一点纸的暖 |
| 面 | `#ffffff` | `#151514` | 纸面、面板、表格 |
| 前景 | `#141413` | `#ecebe6` | 正文、主按钮 |
| 次要 | `#6f6e69` | `#9c9a93` | 次要文字 |
| 细线 | `#e8e6e1` | `#262624` | 边框、分隔 |
| 教练 | `#b8532f` | `#e2845f` | 只用于教练：回复标记、建议中的新增文字、提醒、当前上下文 |
| 问题 ①②③ | 琥珀、玫瑰、鼠尾草，约 30% 透明 | 同色降低亮度 | 句子高亮，当前问题加深 |

状态：做到／改善用绿，部分做到／反复出现用琥珀，均配文字，不单独用颜色表达。

### 7.3 组件

- 基于 shadcn/ui（base-nova），不自造同类组件：Sidebar、Dialog、DropdownMenu、Tabs、ToggleGroup、Table、Tooltip、Sheet、Popover、Badge、Skeleton、Sonner。
- 按钮：主按钮为前景色实心胶囊，次按钮为描边胶囊，工具按钮为无边框图标按钮；高度 32px。
- 圆角：面板 12px，输入框 8px，按钮胶囊。
- 用细线和留白分隔；只有浮层（菜单、弹窗、选区工具条）有阴影。
- 列表用表格行，不用一行一张卡片。
- 动效 150ms，只回应操作：槽位填亮、面板展开、提醒滑入。
