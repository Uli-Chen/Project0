# 第一次改写与对比

版本：0.2-draft。维护：AG-PLAN 起草，创始人批准；问题状态判定规则需签约评分专家审核。基线来源：原方案 §3.2、§4.3、§5.5。关联：[ADR-001](../decisions/001-mvp-scope.md)、[ADR-003](../decisions/003-scoring-evidence.md)。

## REVI-001 — 改写关联与独立评分

- 每个首稿闭环最多一份首次改写提交；局部 Tutor 尝试不属于整篇改写。后续第二轮整篇改写留待下一阶段。
- parent_submission_id 指向原稿，root_submission_id 与原稿相同；同一用户、题目和题目版本，不允许跨用户、跨题目绑定。
- 改写提交前可自由编辑并恢复草稿。正文与原稿完全相同则拒绝并提示尚无修改；不要求达到某个“改动百分比”。
- 并发或重试不会创建第二份首次改写；数据库对 root_id + revision_index=1 设唯一约束。重复请求使用相同幂等键返回原结果；不同正文且首次改写已存在时返回冲突。
- 原稿必须有完整反馈结果才可发起改写。改写评分不读取原稿分数或 Tutor 对话，使用该闭环固定 pipeline。
- 若固定模型版本已不可用，默认阻止直接分数比较。操作员可发起同一新版本下的成对重评，保留旧结果与费用事件；成对完成前不展示分差。

## REVI-002 — 文本变化与问题处理

- 以不可变文本计算词级差异，句级辅助定位；插入、删除、拆句、合句均可展示。
- 问题的原始证据位置始终指向原稿；改写证据重新分句，显式记录映射，不能重用相同数字就假设指向同一句。
- 每条原稿问题在比较结果中标记 `resolved`、`unresolved`、`uncertain`、`removed` 之一，并附理由与改写证据。
- 删除整段导致原问题不再出现时可以标为 `removed`，不能推断已经学会；无法可靠判断时用 `uncertain`。
- 展示两篇分项与总分，可增加、持平或降低；不强制“至少提高 0.5”。页面说明“本次改写表现不等于独立能力提升”。
- 分数比较必须绑定两个 evaluation_id 和同一 pipeline；不可评分或比较失败时显示对应原因，不制造提升结果。

## REVI-003 — 闭环完成

系统完成条件：原稿完整结果、改写完整结果和 comparison 全部持久化且可读取。学习闭环完成条件另加：用户首次打开该对比页，由服务端幂等记录 completion。

反思输入为可选，不作为本阶段完成门槛；未打开对比页只算“结果已就绪”。问题全部解决或分数提高都不是闭环完成的必要条件。

本阶段记录 assisted=true、最高提示级别和证据，不更新长期 mastery，不输出“能力提升百分比”。未来画像只可在新的学习效果设计下使用这些辅助表现数据。

## 验收与假设

验收：AC-011、AC-012、AC-013。任务：MVP-012、MVP-013、MVP-015。

待验证：对比是否帮助理解修改；用户是否把一次改写分差误解成稳定能力变化。试用报告单独记录这两项。
