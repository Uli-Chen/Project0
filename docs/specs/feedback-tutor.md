# 反馈与 Tutor

版本：0.2-draft。维护：AG-PLAN 起草，创始人批准；错误分类与提示原则需签约评分专家审核。基线来源：原方案 §4.3、§5.7、§8.3～8.4。

## FEED-001 — 有依据的重点反馈

- 从有效评分候选中选择最多 3 条不同问题，按影响与证据可信程度排序。首篇没有复发历史，不使用 recurrence，也不生成“你经常……”等措辞。
- 有效问题不足 3 条时展示实际数量；不为了凑数生成错误。零条时仍允许自主修改并比较。
- 每条关联 submission_id、evaluation_id、sentence_id、字符区间、错误类型、中文解释和 L1 提示。区间必须落在该快照中；引用内容与原文一致。
- 标题 ≤20 字、解释 ≤60 字作为软展示目标；准确性优先，超过时走有限修复或安全摘要，不能裁断关键解释。
- 后端检查引用存在只是基础验证；签约评分专家抽检还需判断问题成立、解释合理、提示不误导。
- 反馈失败时保留已生成分数，显示“反馈暂不可用”及重试入口；不得创建新评分或算作完整评估成功。

## TUTR-001 — 受服务端控制的三级提示

| 级别 | 返回内容 | 解锁条件 |
|---|---|---|
| L1 | 指出位置和方向 | 反馈页默认 |
| L2 | 一个引导问题 | 用户请求进一步帮助 |
| L3 | 一句示范及原因 | 用户在该问题下提交两次有效局部尝试，均未解决 |

有效局部尝试必须非空、与上一次尝试不同且关联当前问题；记录输入哈希、尝试序号和检查结果。只点击“还是不懂”不计为一次尝试。局部检查失败或 uncertain 不算“确认未解决”，不自动提高提示等级。

服务端根据历史记录决定级别，忽略客户端越级请求。MVP 不提供 L4 或完整范文接口。回复一般 ≤120 字中文加必要英文示例，以问题或明确动作结束；模型请求代写时引导先写句子。

每个闭环最多接受 12 次成功的额外 Tutor 回复，每次输出上限 512 tokens；L1 初始提示不计入。成功额度通过事务计数，重复请求不重复计数，失败不扣额度。达到上限仍可直接完成改写，不出现支付阻断。该限额是当前成本控制假设，配置变更需记录，不代表未来商品权益。

提示关联用户、问题、作文快照和版本。请求中作文和用户文字均作为不可信输入，不允许修改分数、读取其他用户数据或调用外部工具。服务端输出校验未通过时返回可恢复错误。

## UI 与异常

用户可以不使用 Tutor 直接改写；不能把提示使用设为完成闭环的必要条件。断线后显示已持久化回复；同一请求重复发送返回原回复。问题已属于被删除作文时不再处理或返回正文。

## 验收与假设

验收：AC-009、AC-010。任务：MVP-009、MVP-010、MVP-011。

待验证：三条问题的认知负担、两次尝试后示范是否合适、12 次回复是否足够。准确率与用户理解分别评测，不能以点赞替代问题真实性。
