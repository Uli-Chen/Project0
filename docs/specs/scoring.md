# 评分

版本：0.2-draft。维护：AG-PLAN 起草，创始人批准；量表与标注规则由签约评分专家定稿。基线来源：原方案 §5.4、§5.8、§8、§9。关联：[ADR-003](../decisions/003-scoring-evidence.md)。

## SCOR-001 — 输入与版本

评分只读取题目、不可变作文、Rubric 和确定性特征；不读取用户历史分数、画像、Tutor 对话和原稿分数。改写以独立评分请求处理。

每个 pipeline 清单固定：题目格式、Rubric/量表规则、Prompt、模型及参数、分句与特征、错误分类、校准器、输出 Schema 版本。供应商只提供滚动模型别名时如实记录别名和返回的版本字段，不宣称精确可复现；每日锚点回归检测漂移。

签约评分专家需要明确 Task 2 单篇总分聚合、维度允许值和舍入规则；页面只称“本篇 Task 2 AI 预估”，不输出整场 Writing 成绩。版本化量表作为 MVP-002 交付物，不能直接把示意分数当正式规则。

## SCOR-002 — 处理管线

1. 输入检查与分句，计算规则特征；规则工具发现的是候选信号，不能直接视为真实语言错误。
2. 评分 A/B 并行，分别输出维度、证据、候选问题和不可评分标记。
3. 总分差 ≥0.5、任一维度差 ≥1.0 或有效异常标记触发仲裁；阈值是初始策略参数，需实验验证。
4. 无仲裁时，原始共识采用各维度 A/B 算术平均，再按版本化量表聚合；有仲裁时采用经 Schema 校验的仲裁结果。校准输入保留原始 A/B 与分歧，不丢弃来源。
5. 应用已验证且与本 pipeline 兼容的校准器，再做量表约束检查；无有效校准器时只能在开发演示模式返回标识明确的原始结果。
6. 评分结果先持久化，再生成教学反馈；两个阶段失败分别记录。

缺失维度、越界分数、非法枚举、无效引用必须拒绝；单阶段格式修复最多 1 次，后续按运行支撑的有限重试策略处理。不得以零分或历史分数代替失败结果。仲裁不可用时不静默平均后冒充完成。

## SCOR-003 — 展示与区间

- 展示分项、原文依据和“AI 预估”；模型自报 confidence 不直接解释为正确概率。
- 区间缺省为 null。仅在独立数据上验证区间覆盖率与宽度后开启；响应携带区间方法、名义覆盖率和版本。
- 异常或不可评分返回具体状态和改善输入的方法；没有足够依据不强行生成分数。
- 首个分数 P95 <15 秒、完整反馈 P95 <30 秒是原方案目标，必须实测，包含排队、重试和持久化，不按首个 loading 事件计时。

## SCOR-004 — 质量关口

离线协议见 [评分评测](../validation/scoring-benchmark.md)。主要保留原方案门槛：±0.5 命中率 ≥80%、MAE ≤0.4、QWK ≥0.75、各分段偏差绝对值 ≤0.25；重复评分标准差 ≤0.25。以上均为待测目标。

训练校准、调 Prompt 和最终测试必须隔离；同一学生/题目/改写链不跨分组。最终测试集反复用于调参后应退役为开发集，重新建立测试集。

对比单评、双评、仲裁、校准的准确率与成本，允许证据支持后简化架构，但必须更新 ADR 和回归。双评一致性本身不是准确性证据。
