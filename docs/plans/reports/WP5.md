# WP5 速刷界面与卡片复习

2026-11-01。实现由主代理完成，独立审阅后修复交互并发风险。本报告列出代码与自动化证据；浏览器证据由 WP8 汇总。

## 实现

- 速刷独立 `QuickScreen`，按功能开关在会话页分派；三栏呈现追问、本人卡片与检查结果。每题要求按冻结的 requirements 显示。
- 学生可以直接输入、保存、回答追问、选取本人原话摘取到指定槽位、检查、重试、补充检查、搁置与恢复、转成精练。
- 模型检查运行时可继续编辑保存；旧版本结果显示待重查。技术失败、内容不足、超额、中断与 stale 分开呈现。
- 卡片复习页与精练中的冻结来源由 WP5 主实现提供。按钮根据服务端 defaultDeepId 显示“用这张卡写成作文”或“打开作文”；原子练习已删除时明确另开。

## 独立审阅修复

1. 显式另开：同步 latch 防止 React 更新前双击；每次意图使用稳定幂等键，并仅将不含正文的键存入 sessionStorage。网络响应丢失、页面刷新后重试复用同一键。
2. 首次读取、轮询、手动刷新统一按 mutation epoch、请求序号、会话和卡片版本接收快照。延迟旧 GET 不再覆盖新保存；完成模型请求也使旧 GET 失效。
3. 续写/搁置/摘取短请求锁定编辑区，保存前后的 editRevision 再校验；模型长请求不锁卡片编辑，保留并发保存能力。
4. 摘取返回只更新对应槽位，要求本地编辑版本及服务器卡片版本未发生变化。
5. 发送回答同步去重，短请求期间禁用回答编辑，且成功清空前确认仍为原提交值。
6. 站内首页/复习链接使用 Next Link onNavigate 保护未保存卡片与未发送回答；硬刷新/离开使用 beforeunload。

`lib/quick/client-state.ts` 承载可单独验证的快照接收、同步 latch、编辑版本和持久意图键逻辑。

## 浏览器验收后的离开确认修订

原生 window.confirm 在验收浏览器中会阻塞 CDP。改成页面内 role=alertdialog 的明确确认区域，不绕过未保存保护：默认焦点为“继续编辑”，另一选项为“放弃未保存并离开”；未发送回答转作文时单独说明卡片会先保存。Escape 可返回编辑。保存/发送期间禁止确认跳转。硬刷新 beforeunload 保留。

新增 tests/ui/quick-leave-confirmation.test.ts：普通离开/未发送回答两类文案、可访问命名和保留编辑选项、忙碌时按钮禁用。lint/typecheck 通过；UI 27/27。
