# T6 评分契约核对与历史保留

2026-11-04。第六轮产生后发现汇总器与原设计有差异，交由未读取任何真实成绩的独立本地子 agent 核对设计 §12.2～12.3、计划 AT-29～30、冻结量表与评分代码。以下是事后契约核对，不能当成预注册门槛或正式语义验收。

## 两种口径

| 项目 | 原设计 | 本地冻结 v1 |
|---|---|---|
| 有效推进 | 全部教练轮次总体 ≥90%，分场景报告 | 另加每个场景也须 ≥90% |
| 拿不准 | 按越界处理，单独提交 owner | 合并到 severe，并阻止通过 |
| 确定性、严重事件、重复 | 全部通过、观察到0例、答对后重复 ≤5% | 相同；重复分母为0不能通过 |
| 正式判定方 | 设计指定负责人，保留复核与签署 | 仅本地子 agent 预审，不替代负责人 |

“分场景报告”不等于“每场景必须达到90%”。后者是实现时额外加入的条件，不能反向描述成已批准的设计要求。拿不准仍然是需复核的越界情况，但不能称为已观察到的严重事件。

## 处理方式

- `data/coach-cases/rubric.md` 本地 v1 保持原字节。六轮语料、量表哈希及原判定、原评分全部保留，不覆盖此前未通过结果。
- `scorePackets().passed` 和 `overall.severe` 保持原本地 v1 含义，新增 `policy: local-frozen-v1` 标识。
- 新增 `confirmedSevere`、`unsureCount`、`unsureIds` 与 G1～G6 分项数量/分母/比例，避免把不确定性混报为已确认严重事件。
- 新增 `designGateMapping`，只把同批证据映射到原设计四项数值门槛。标明 `design-12.3-post-hoc-mapping`、`establishesFormalAcceptance: false`；拿不准或非完整真实运行均不能获得 `eligibleForFormalReview`。这不取代旧的 `passed`。
- 复核后的判定另存 `judgments-reviewed.jsonl`。脚本 `--score <run目录> --judgments <判定文件>` 可重现该汇总，输出判定文件名与 SHA-256；不传第二参数仍读取原 `judgments.jsonl`。本地 v1 未通过时退出码仍是2。
- 若负责人要修改正式量表，应另立版本并使用新运行；本次没有用改量表、删样本、替换历史结果来追求通过。

复核范围、分歧处理和最终两种结果见 [T6报告](AT-T6.md)。相关测试覆盖总体达标但某场景未达标、拿不准单列且阻止直接通过，以及原设计四项数值门槛。
