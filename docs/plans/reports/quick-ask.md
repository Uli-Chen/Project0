### 第 3 轮（v14）：缩短提示词

合并后发现 T10 失败：v13 提示词变长后，第二次开口的准入估算超过单次 4000 的上限（估算按 UTF-8 字节计，中文一字算 3）。v14 把提示词从 1,662 字节压到 1,167 字节，规则不变。机器判定 8/8；但 A1“你在家读大学时……”和 A4“你离家生活时……”又开始假设学生的个人经历，A1 还读不通。未采用。

## 浏览器验收（§7.3）

环境：`web-full` 预览（localhost:3125，`data/dev-full.sqlite`），测试账户，科技题新卡片，1440×900 与 375×812。提交 `ed8b734`，提示词 v15（教练问题内容的问题已在 v16 处理，交互部分与提示词版本无关）。

| 场景 | 结果 |
|---|---|
| 空卡片点示范问题 | 学生气泡立即出现，接着是教练等待动画和问题；示范问题气泡下没有“放进卡片” |
| 回答教练 | 回答气泡下有“放进卡片”；底部回到示范问题加输入框，下方显示“还可以追问 1 次” |
| 断网时自己打字发送 | 错误显示在教练面板输入框上方（“连接中断，内容还在本页。”和“重新发送”），文字留在输入框 |
| 请求到达服务器但响应丢失，再点重新发送 | 两次请求用同一个 requestId 和原 cardVersion；对话里这句话和教练问题各只出现一次，回答框为空（验收意见 A1、A2） |
| 追问用完 | 底部换成“这张卡的追问用完了，可以接着改卡片，或直接检查。”，没有输入框 |
| 手机宽度 | 顶栏显示“教练”按钮和保存勾号；教练在右侧抽屉里，对话和底部状态完整 |
| 另一处改了不同的栏 | 本页继续编辑后自动合并：另一处的“理由”出现在本页，本页的“观点”保留并保存（审查 W1） |
| 另一处改了同一栏 | 顶部提示“这张卡在另一处也改过”，该栏下方显示另一处的版本和“用我的 / 用另一处的”，选择前不保存；选“用我的”后服务器内容正确 |
| 作文页、作文列表、进展页在 375px | 作文页顶栏下有计时、字数、保存状态一行；作文列表为两行列表；进展页文案为“独立模考” |

未覆盖：检查通过后再修改卡片（W15，需要一次检查调用）；作文评估后的蓝色问题标记（需要评估调用），交给 astra 的代码审查。


准入估算 `utf8-byte-v1` 刻意按字节计（字节级分词的最坏情况），对中文约高估 5 倍：本轮真实输入约 580–630 token，估算约 3,000。单次上限 4,000 时，按 `.local/est.ts` 的测算：

| 卡片与对话 | 原追问提示词 | 自由输入提示词（v15） |
|---|---|---|
| 空卡片，1 条消息 | 2,770 | 约 3,050 |
| 4 栏各 60 字，4 条消息 | 4,134（超限） | 约 4,410（超限） |
| 4 栏各 150 字，4 条消息 | 5,214（超限） | 约 5,490（超限） |

也就是说，卡片每栏写到 60 个字左右、聊过两轮后，第二次追问会被拒为“输入过长”。这个问题在自由输入之前就存在。可选做法：提高速刷的单次和包内输入上限（升 `budgetConfigVersion`），或者改用按字符计的估算（升 `inputEstimateVersion`，失去字节上界的保证）。两者都涉及成本策略，本次没有改。

**2026-11-14 更新：** 负责人同意放宽。`budgetConfigVersion` 升为 `quick-budget-20261114-v2`：单次准入从 4,000 提到 16,000，初始包输入从 20,000 提到 40,000，补充包从 8,000 提到 20,000，用户每日上限不变。写满的卡片加上对话都能通过；结算仍按模型返回的实际用量计。
