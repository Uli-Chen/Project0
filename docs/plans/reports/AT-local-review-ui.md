## Seed 合同与静态检查

每个 case 都明确 `seed: { draft, issue, messages, thread }`。issue 为实际问题对象或 null；messages 是带稳定合成 ID 的学生/教练消息；thread 为真实 TeachingState 结构或 null。运行器应消费 seed，不能继续使用统一公共交通稿件/统一语法句。`expectations` 仅作 corpus 维护对照，不进入模型输入、盲包或独立语义评审上下文。

检查通过：30 个 case 的 actions 均通过真实 `actionSchema`；所有非空 seed thread 均通过 `readTutorState`；所有 established 引用均指向本例学生消息且文字是该学生消息的连续原文；lastMessageId 存在且与相关末条消息对齐；issue/prewrite 入口、问题对象及 seedHistory 长度一致。

30 例全部多轮，每轮完整重复集共 72 个教练请求，重复 3 次为 216 个请求（技术重试另计）；轮数未增加。题型分布为 opinion 9、discussion 6、advantages 6、problem_solution 4、two_part 5；讲解语言 en/zh 各 15；argument 27、language 3。该分布不意味着各组具有统计代表性。

## 量表冻结

`rubric.md` 在真实运行前冻结为本地 v1，要求保存文件/语料哈希，禁止看结果后追改。它明确了 G1～G6、严重程度、有效推进、拿不准、失败样本、重复分母、固定回放局限及来源快照边界。

`previousCorrect` 依据被评教练回复之前最近一次实质学生作答，可为当前输入，不允许只看 history 最后一条。原样引用学生已提供的正确句不等于新代写。量表不把协议 move 或 help 声明当作语义事实，不把合规拒绝代写自动判为无效。当前评分器要求总体及每场景有效推进 ≥90%，并保持其余既定门槛；未改变程序 gate。
