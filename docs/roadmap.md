## 三种可用状态

1. **开发演示**：允许合成数据与模型模拟，界面明确标识，不开放给真实学习用户。
2. **免费封闭试用**：实际评分须通过 [评分门槛](validation/scoring-benchmark.md)，P0 验收全部通过；创始人作为故障、删除和用户支持的负责人，已公布支持时段并能按步骤执行恢复与删除。
3. **公开收费**：不在 MVP-1 范围；需补支付/权益/退款、容量和运营方案，重新评审后建立下一阶段关口。

原方案 Alpha 的 500 篇专家评分数据是规划目标。本阶段需先完成数据获取与独立测试设计；未收集、未测量时不得将评分门槛标为通过。CI 未校准时可以不展示区间，但必须明确显示“AI 实验性预估”，不能虚构 5.5–6.5 等区间。

## 暂缓事项及恢复条件

| 项目 | 暂缓原因 | 重新评估条件 |
|---|---|---|
| 长期画像、自动规划 | 单次改写不足以推断掌握度 | 有多篇独立作文证据，并定义新题迁移验证 |
| LT/支付/订阅 | 首次完整体验不应被额度截断 | 首闭环体验明确、价格与权益另有规格 |
| L4 完整范文与微练习 | 增加教学和内容验收范围 | L1～L3 试用暴露明确需求 |
| 其他考试、OCR、小程序 | 需要不同输入和任务适配 | 首个闭环通过试用复盘，建立题型适配器接口 |
| 后台、数仓、复杂基础设施 | 当前可先用受控脚本和报告完成 | 使用量或运营频次证明手动方式不适用 |

## 结束 MVP-1 时必须回答

- 用户能否完成整个流程，在哪一步退出？
- 问题与提示是否准确、可理解，用户是否真正改写？
- 评分质量、调用成本、恢复能力和延迟是否达标？
- 下一步优先改善体验、评分还是增加训练内容，有什么证据？

不以“原计划到了某个日期”作为扩考试或开放收费的理由。
