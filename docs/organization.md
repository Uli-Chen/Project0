# 团队与组织

文档版本：0.2-draft。更新：2026-10-23，Asia/Taipei。关联：[ADR-004](decisions/004-opc-agent-organization.md)。取代冻结基线商业计划书第九章的人力计划（6→24 FTE），原文保留在 [v0.1 快照](baselines/v0.1/README.md) 中供追溯。

## 组织形态

WriteMentor 由一家台湾登记的一人公司（OPC）运营，主要服务大陆成年用户。主体所在地与用户所在地不同，合规路径尚未确定（见待决事项 Q-001）。组织上：**一名创始人承担全部决策与对外责任，多个 AI Agent 承担起草、开发、评审、验证和运营准备工作**。不设员工编制；需要人类专业判断或法定资格的工作通过按件或按时签约的外部人员完成。

三条基本原则：

1. **Agent 产出，创始人决定。** Agent 可以写规格草稿、代码、测试和报告，但范围、放行、合并、对外沟通、花钱和接触真实用户数据只能由创始人决定。
2. **作者不验证自己。** 同一任务的实现与验收由不同 Agent 角色、不同会话完成；验证结论须附可复现命令或证据，创始人可以重跑。
3. **人类判断不可被模型替代的地方，明确交给人。** 专家评分、反馈准确性抽检、试用访谈和法律意见不得由 Agent 代做或以模型互评代替。

## 角色

### 创始人（唯一人类成员）

| 职责 | 说明 |
|---|---|
| 范围与优先级 | 批准规格冻结、ADR、任务转 `ready`、切片放行和下一阶段决策 |
| 合并与发布 | 唯一可以合并到 `main`、创建标签、修改生产配置和开启真实用户邀请的人 |
| 验收确认 | 抽查或重跑验证 Agent 的证据后，才把验收结果确认为 `passed` |
| 数据与凭据 | 唯一持有生产密钥、受控样本存储和真实用户数据访问权；负责个人资料处理的对外责任 |
| 对外 | 联系试用用户、签约评分专家与顾问、处理付款与合同 |
| 运营值守 | 试用期间的故障和删除请求最终负责人；按下文支持时段响应 |

### Agent 角色

每个 Agent 会话只承担一个角色，并且只处理一个任务编号。同一角色可以开多个并行实例，受下文在制品上限约束。角色代号用于 [任务台账](tracking/tasks.md) 的“执行／审批”列，由检查脚本校验。

| 代号 | 角色 | 主要产出 | 不得做 |
|---|---|---|---|
| AG-PLAN | 规划 Agent | 规格与契约修订草稿、任务拆分、ADR 草稿、周检报告草稿 | 自行批准范围或改变验收门槛 |
| AG-DEV | 开发 Agent | 在独立分支/工作树中实现单一任务，附测试与运行说明 | 合并 `main`；改动无关模块；对不清楚的需求自行发明行为 |
| AG-REV | 评审 Agent | PR 代码、安全与规格一致性评审意见 | 评审自己写的代码；直接修改被评审分支 |
| AG-QA | 验证 Agent | 执行验收、故障注入与权限测试，写 [验证报告](validation/runs/README.md) | 验证同一会话实现的代码；为通过测试修改产品代码或降低门槛 |
| AG-EVAL | 评测 Agent | 数据划分、评分管线离线评测、组件对比和回归报告 | 生成或修改专家标签；用测试集调参 |
| AG-OPS | 运营 Agent | 监控与告警汇总、故障分诊、删除/导出操作的执行草案、用户回复草稿 | 直接向用户发送消息；在未经批准时操作生产数据 |

AG-OPS 只在 S3 试用准备之后启用。开发阶段的监控和日志问题由 AG-DEV/AG-QA 处理。

### 外部签约人员

| 角色 | 数量与时机 | 职责 |
|---|---|---|
| 雅思写作评分专家 | 至少 2 名，MVP-002 开始前签约 | 审核量表与标注手册；独立双评专家样本；参与反馈准确性双人抽检（AC-008、AC-009） |
| 两岸法务／个人资料顾问 | MVP-006 选型前完成首次咨询；公开收费前再评估 | 台湾主体服务大陆用户的路径：ICP 与生成式 AI 登记、PIPL 境外处理者义务、数据存放与传输、台湾方面的赴陆投资或合作许可、服务条款与隐私告知（见待决事项 Q-001） |
| 会计／记账 | 按台湾登记与报税要求 | 公司账务、营业税与支出凭证；未来收取人民币款项时的收款与结汇方式 |

签约人员不获得代码仓库写权限。接触样本时只使用受控存储中的匿名作文，签署保密与使用范围约定。

## Agent 权限边界

| 资源 | Agent 默认权限 | 由创始人掌握 |
|---|---|---|
| 代码仓库 | 读；在 `<type>/MVP-xxx-*` 分支提交；开 PR | 合并、标签、删除分支、修改冻结基线 |
| 模型 API | 开发用密钥，设单独额度上限 | 生产密钥、额度调整 |
| 数据 | 合成数据与公开样例 | 授权专家样本、真实用户作文、生产数据库 |
| 外部沟通 | 无 | 用户、评分专家、顾问、供应商 |
| 费用 | 无 | 任何付费服务开通与续费 |

Agent 发现以下情况必须停止并在任务卡或 PR 中提出问题，不得自行假设后继续：规格缺失或矛盾、需要改动其他任务的边界、需要真实数据或生产凭据、需要放宽任何验收数值。

## 人工与 Agent 的分工边界

| 工作 | Agent 可做 | 必须由人完成 |
|---|---|---|
| 评分量表与标注手册 | 起草、整理官方公开描述 | 评分专家审核定稿 |
| 专家样本评分 | 准备匿名清单与表格 | 两名专家独立评分及仲裁 |
| 反馈准确性抽检（AC-009） | 抽样、去重、汇总统计 | 两名人工评审判断问题成立与引用正确，至少一名为签约专家 |
| 代码与测试 | 实现、评审、执行 | 创始人合并 |
| 验收结论 | 执行并提交证据 | 创始人确认 `passed` |
| 试用访谈 | 准备提纲、整理匿名记录 | 创始人进行访谈 |
| 下一阶段决策 | 汇总数据、起草 ADR | 创始人决定 |

模型给模型打分可以作为开发期回归信号，但不能作为 AC-008、AC-009 的通过证据。

## 节奏与容量

创始人的评审时间是首要瓶颈，流程按它设计：

- **在制品上限**：同时处于 `in_progress` 的开发任务不超过 2 个；等待创始人评审的 PR 不超过 3 个，超出时 Agent 先暂停新开发，转去补测试或文档。
- **PR 大小**：一个 PR 只覆盖一个任务内一个可验证的子项，并在描述中写明如何复现验证。
- **每周检查**：创始人每周一次查看阻塞、待决事项和一个可运行的用户流程演示；AG-PLAN 先起草周检报告，记录在 [周检记录](tracking/reviews.md)。
- **试用支持时段**：台北时间工作日 10:00–18:00 内首次响应不超过 1 个工作日；删除请求按 CORE-004 的 7 天时限完成。非支持时段的故障由告警记录，次个支持时段处理，并在试用说明中事先告知用户。

## 单点风险

一人公司没有备岗。缓解措施：

- 生产凭据与恢复步骤存放在带紧急访问的密码管理器中；部署、回滚和删除操作写成可由他人按步骤执行的说明（MVP-016、MVP-017 交付）。
- 创始人连续 3 个工作日以上不可用时，暂停新的试用邀请，已开放用户可继续使用并导出数据。
- 所有决策写入 ADR 或任务卡，不依赖某次 Agent 会话的上下文。

## 费用归类

研发用 Agent 与工具费用记为研发费用，不计入产品的单次闭环 AI 成本（CORE-002 的 <¥0.50 只统计面向用户的模型调用）。外部评分专家费用记入评测数据成本。当前没有实测费用，相关预算由创始人另行维护。

## 扩张规则

不预设年度编制。只有在以下情况持续出现时，才评估签约或招聘人类成员，并新增 ADR：

| 触发信号 | 可能增加的人 |
|---|---|
| 新考试线需要建立独立量表与专家样本 | 该考试线的签约评分专家 |
| 用户支持在支持时段内无法按时响应，且已用 AG-OPS 草稿与 FAQ 分流 | 兼职客服 |
| B2B 客户要求现场或固定窗口的销售、实施 | 兼职或全职销售／客户成功 |
| 创始人评审排队持续超过在制品上限两周以上 | 兼职技术评审或工程师 |

原商业计划书的人力成本、融资用途（“6 人核心团队”）和营收模型的人力行均基于旧编制，已与本组织形态不一致；在重新建模之前，不应引用其中的人力与融资数字。
