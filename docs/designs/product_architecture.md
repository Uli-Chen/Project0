## 1. 产品定义

### 1.1 一句话

**project 0 是一个雅思写作陪练：学生每次打开有一件明确的事可做，写完能改好一个最重要的问题，下次回来系统知道该继续帮他，还是让他独立试一次。**

- **对谁：** 中国大陆的成年雅思考生，用中文构思，常在手机上使用（agent_tutor §2）。默认强度跟着基准模考的实测分数走（§3.4）；试用者按现 6.0 左右、目标 6.5～7 招募（owner 决定）。
- **解决什么：** 有想法但展不开，审题不全，中文想好了英文写不出，同类错误反复出现（user_workflow_v2 §3 的 D1～D5）。
- **与通用 AI 的区别：** 内容来自学生自己的想法；每篇推进一个问题并核验是否改好；记录每次得到了多少帮助，只把新题上独立做到的算作进步。

### 1.2 设计原则

| 原则 | 含义 | 对设计的约束 |
|---|---|---|
| 明确的默认动作，自由的出口 | 学生不需要自己判断下一步练什么，但随时可以自己选 | 首页只突出一件事，由代码规则决定；所有模块在导航里直达 |
| 从学生的想法出发 | 立场、理由、例子来自学生；语言知识可以直接讲 | 沿用 G1～G6；论证求助先试后给（§5.4） |
| 帮助跟着证据减少 | 同一技能下次从更少的帮助开始 | 每次帮助都记录；只有未提示的新题迁移算独立 |
| 评分、核验、教学三类隔离 | 教练越了解学生越好，但判分和判“做到没有”的一方不能看到辅导历史 | §5.1 的权限表 |
| 代码管规则，模型管措辞 | 状态转移、计数、推荐、权限、来源校验由代码完成 | 模型不写账本，不决定“今天做什么” |
| 记录按证据等级使用 | 行为记录只能展示，不能改变学习状态 | §2.2 |

### 1.3 考试与题型范围

| 阶段 | 范围 |
|---|---|
| 核心闭环试用（§12 阶段 1） | 雅思学术类 Task 2，五种题型，沿用现有题型定义 |
| 公开上线前（阶段 2） | 增加 Task 1 的题库、评分和完整基准模考（Task 1 + Task 2，60 分钟） |
| 之后 | Task 1 的辅导、卡片和复习；其他考试。各自的采用条件见 §12.2 |

`ExamType`、`TaskKind`、`RubricVersion` 的抽象在接入 Task 1 时一起做，不提前实现。

### 1.4 非目标

- 不给范文、整段示范或模板（G4）。
- 不做连续打卡、排行榜（题库设计已列为非目标）。
- 不做人设、多角色讨论、无限自主循环（agent_tutor §3）。
- 不让模型决定推荐、写账本或宣布掌握。
- 不在评分校准通过前向公开用户展示单点分数（商业计划备忘录 §10）。
- 第一阶段不做 Task 1、邮件提醒、学习者画像、60 分钟联考。

## 2. 学习闭环与成果判定

### 2.1 核心闭环

```text
今天（一件事）→ 卡片或完整作文 → 批改报告 → 改好一个问题（核验）→ 记录：首次尝试、用过的帮助、核验结果
      ▲                                                                              │
      └───────────── 下次的“今天”：没改完的问题、到期复习、已有卡片的题 ◄──────────────┘
基准模考（注册赠送一次，之后定期）→ 不靠教练的成绩 → 默认强度、成绩趋势
```

每个环节回答一个问题：

| 环节 | 回答什么 |
|---|---|
| 今天 | 我现在该做什么，为什么，要多久 |
| 卡片 | 题目问的每一点我怎么答，为什么 |
| 完整作文 | 我能不能把想法写成一篇 |
| 报告 | 最值得改的是哪里 |
| 改一个问题 | 我改得动吗，改对了吗 |
| 复习 | 我还记得吗 |
| 基准模考 | 没有教练时我是什么水平 |

### 2.2 证据等级

沿用 user_workflow_v2 §2.3，并补上本文新增的几种记录。等级低的记录只能展示，不能改变排期之外的学习状态。

| 记录 | 能确认 | 不能确认 |
|---|---|---|
| 复习里的闪卡自评（记住了 / 还不稳） | 学生自己的判断 | 是否真的记住。只用于复习排期，不进入能力账本 |
| 学生看过参考视角后写的卡片内容 | 学生写下了这些内容 | 想法是不是自己想到的。不算独立证据，不进入个人素材（§5.4） |
| 隔离核验给出的“解决 / 部分 / 没解决” | 在评测集覆盖的情形下大体可靠 | 评测集以外的情形 |
| 学生声明“没在别处练过这道题” | 学生的声明 | 是否属实。基准和净题模考都依赖它，如实标注 |
| 画像备忘绑定的原句 | 学生说过这句话 | 模型的归纳成立（agent_tutor §8.3） |

### 2.3 成果的三种等级

沿用 agent_tutor §9.2 和 user_workflow_v2 §6，不另定义：

| 成果 | 条件 | 能用来做什么 |
|---|---|---|
| 帮助后做到 | 本稿有涉及该技能的帮助事件，之后核验达成 | 本次任务完成，不算进步 |
| 知道重点后做到 | 预告了重点，首次尝试达成，之前没有针对性帮助 | 可以安排新题检验 |
| 未提示的新题迁移 | 新题，不预告，没有针对性帮助，首次尝试达成 | 算作进步 |

每次任务记三件事：首次尝试的结果、之后用过的帮助、最终核验结果。图表和进展页默认只用首次尝试的结果。

### 2.4 能力状态规则

`observed_once`、`recurring`、`improving` 的条件以 agent_tutor §9.3 为准，本文不重写。其中两条在 v1.0 里被改掉了，这里恢复：

- **没出现不等于已通过。** 一篇最多报告 3 个问题，没被报告只表示“未报告”，不计入分母。
- `improving` 需要最近 2 篇有专门核验的新题原稿都达成，其中至少 1 篇属于“知道重点后做到”或“未提示的新题迁移”。

这些状态依赖评分输出版本化的分类码，分类码依赖分类表 v2 的离线校准（agent_tutor §9.4）。校准通过之前，产品不显示自动判定的“复发”或“改善”，现有的“上次也出现过”标注保持现状。

## 3. 信息架构

### 3.1 工作台骨架

**桌面：** 三栏。左栏是可折叠的导航；中栏是当前页面；右栏是统一的 Tutor 面板，可折叠。完整作文和卡片现在已经共用同一套教练组件（`components/coach/`），这一点保留并推广到复习和进展页。

**手机：** v1.0 没有写。初步形态如下，需要在试用前按现有窄屏布局核对：

| 部分 | 手机上的形态 |
|---|---|
| 导航 | 底部导航或抽屉 |
| Tutor | 从底部拉起的面板，覆盖在内容上，可随时收起 |
| 卡片、复习、今天 | 手机优先设计。这三件事单次 5～10 分钟，是手机上最自然的使用 |
| 完整作文 | 沿用现有的写作 / 提纲 / 教练切换 |
| 模考 | 可以在手机上做，但开始前说明正式考试是机考，建议用电脑 |

工具入口不能只靠长按选文才能发现（agent_tutor §7 第 2 条）。

### 3.2 导航与题库

- 左栏入口：`今天`、`完整写作`、`题目卡片`、`模考`、`复习`（带到期数量）、`进展`，底部是账户设置。
- 不设单独的题库浏览页。`完整写作` 和 `题目卡片` 进入后是同一个可筛选的选题器，加上粘贴题目的入口和进行中的草稿。已有卡片的题可以一键写成作文，这是现有功能。
- `学情与记忆` 在第一阶段仍是现有的“进展”页。账本和画像的管理视图在阶段 3 加入。

### 3.3 首页“今天”

现有首页已经是一块深色面板，只推荐一件事（user_workflow §2）。v1.1 保留这个形态，改三处：

1. **推荐规则由代码决定，从上到下取第一条满足的：**

| 顺序 | 情况 | 主动作 | 现状 |
|---|---|---|---|
| 1 | 注册后还没做过基准模考，没有选“稍后”，并且还没有任何练习 | 做一次基准模考 | 新增（§3.4） |
| 2 | 有没写完的练习 | 接着写 | 现有 |
| 3 | 最近一篇报告的首要问题还没改，且在 7 天内 | 改这个问题，约 5 分钟 | 新增（§8.1） |
| 4 | 这道题已有卡片，还没写 | 用卡片写成作文 | 现有 |
| 5 | 其他 | 一张新卡片或一篇新作文 | 现有；选哪种见下 |

2. **新练习选卡片还是作文：** 账本可用之前按学生自评的难点选。自评“没想法”或“想法说不清”的默认卡片，其余默认作文。现在的规则是“速刷只在一个主题的第一次出现”，这是 user_workflow §10 的断点 2，改掉。
3. **面板写明理由和总时长。** 时长包括评估等待和改一个问题的时间，不只是写作时间（断点 3）。

- 面板右侧保留现有三行：先复习、这次留意、目标。到期复习不占用主动作。
- 做完主动作后显示完成状态和下一条规则命中的事，学生可以继续，也可以结束。
- 学生随时可以“换一题”或从导航进入任何模块。规则只决定默认值。
- 选题仍在“上次练的主题”里进行。面板写明当前主题，旁边有“换主题”的入口；系统不自动换主题（owner 决定，与 2026-10-31“不把话题作为推荐信号”一致）。这处理的是 user_workflow §10 的断点 1。

### 3.4 冷启动与基准模考

- **注册后只问三项：** 目标分、考试日期或备考周数、自估水平。现有问卷是七项，其余四项（难点、每周次数、每次时长、思考语言）移到账户设置，首页不再因为没填而留空。自评难点用于 §3.3 的规则 5，没填时默认作文。
- **赠送一次基准模考（owner 决定）：** 每个注册用户获得一次完整的限时模考和评分，随机抽题，不消耗 credits。分数作为基准。
  - 试用阶段：基准是现有的 Task 2 独立模考（40 分钟）。现在它要求“完成第一篇精练之后”，这个前置条件去掉。
  - 公开上线：基准是 Task 1 + Task 2，60 分钟，按 1:2 加权。
- **不是强制的。** 学生可以选“稍后”，之后它出现在面板下方的模考邀请里。这与 2026-10-31“不设强制入门测试”的决定一致。
- **没做基准之前，** 默认强度用自估水平。
- **基准分怎么显示：** 评分校准通过之前显示为总分上下各 0.5 的区间（例如 5.5～6.5），并标明是 AI 预估。基准只调整默认值，例如讲解语言的建议、默认练卡片还是作文，不锁定任何功能。

### 3.5 Tutor 面板的会话范围

统一的面板外壳，对话按场景绑定：

| 所在页面 | 面板里的对话 | 说明 |
|---|---|---|
| 一篇完整作文 | 这篇作文的对话 | 写前、正文、每个反馈问题各是一条教学线程（agent_tutor §8.1 的 `threads`），共用一个面板。阶段切换时不需要学生重开对话 |
| 一张卡片 | 这张卡片的对话 | 卡片写成作文时，卡片内容带入提纲，对话不带入 |
| 今天、选题、复习、进展 | 全局对话 | 不在第一阶段。跨练习的咨询依赖账本，在阶段 3 开放 |
| 模考进行中 | 面板收起并锁定 | 界面写明“模考进行中，没有教练”，服务端拒绝所有辅导请求。交卷出分后解锁，进入这场模考的讲评 |

## 5. Agent Tutor

### 5.1 三类调用权限

沿用 agent_tutor §4。v1.0 把核验类调用写成了 Tutor 的工具，这里改回来。

| 类别 | 调用 | 能看到 | 不能看到 / 不能做 |
|---|---|---|---|
| 评分 | 作文与模考的正式批改 | 题目、图表摘要（Task 1）、冻结正文、评分规则、分类表 | 记忆、目标分、基准分、提纲、辅导历史、帮助记录、档位 |
| 核验 | 改一个问题的核验、卡片检查、复习里的改法核验、二稿对比 | 题目、必要的全文、原问题、修改前后的文字 | 不读记忆和辅导历史；不因为接受过帮助而加分或减分 |
| 教学 | Tutor 在各模块的对话 | 题目、当前工作区、教学线程状态、学习者信息切片 | 不能改分数；不能写账本；不能把提示后的成功记成独立掌握 |
| 推荐 | “今天”和题目推荐 | 练习事实、账本 | 由代码完成，不调用模型 |

- 核验由学生的显式操作触发，例如提交修改、点“检查”，由代码发起，不由 Tutor 决定何时核验。Tutor 读到的是核验结果。
- 报告里“是否属于复发问题”的标注，是评分完成后由代码把分类码和账本对上，不让评分调用看到账本。

### 5.2 运行模型

```text
学生操作 → 代码准入（权限、频率、模考锁定）→ 上下文组装（白名单投影）
        → 模型提出教学动作（回复 + 状态增量 + 提案）→ 校验 → 保存 → 展示
```

- **第一阶段：一次交互一次模型调用，不带工具。** 这是 agent_tutor §11.1 的做法，也是现有 `lib/tutor` 的实现。
- **阶段 3 起：** 增加一个只读工具 `query_memory_vault`，用于取证据原文和相关卡片。单次交互最多“1 次只读检索 + 1 次最终输出”。agent_tutor §11.1 已经预留了这个口子。
- **工作区写保护：** Tutor 不能直接改提纲、卡片或正文。所有修改都以建议卡片的形式给出，学生点击采用才生效，并记入帮助事件。提纲、卡片、正文的提案是输出里的结构化字段，不算工具调用。
- **晚到结果：** 正文版本、线程或引用的来源在等待期间变了，整次结果作废（agent_tutor §8.3）。

### 5.3 提示词分层

除评分和核验外，教学调用按四层组装，前面的层保持稳定：

| 层 | 内容 | 何时变化 |
|---|---|---|
| L0 身份与协议 | 角色、讲解语言、不可信输入隔离、输出规范 | 不变 |
| L1 教学准则 | G1～G6、两套帮助阶梯 | 不变。v1.0 在这一层放了模式参数，已取消 |
| L2 模块与阶段 | 当前阶段的职责和允许的教学动作，例如 `essay.prewrite`、`essay.body`、`essay.issue`、`card`、`review` | 按所在位置切换 |
| L3 工作区与学习者切片 | 题目、当前提纲 / 正文 / 卡片、线程状态、§5.6 的切片 | 每次调用组装 |

### 5.4 帮助方式

**语言问题（LR / GRA）：直接帮，对复发弱点先让学生自己改。**

- 划词润色、检查语法、“英文怎么说”直接给建议卡片和简短原因。这是现有功能，owner 已确认保留。
- 例外：账本里标为 `recurring` 的弱点，先指出位置和问题类型，学生点“再给点提示”才逐级给到改法（L0～L3）。这一条依赖账本，阶段 3 生效。之前保持现状。

**论证问题（TR / CC）：沿用 A0～A3 阶梯，另加一个“参考视角”动作。**

- 阶梯不变：写前最高 A2，改写最高 A3，“再给点提示”一次升一级（agent_tutor §10.2）。
- **新增“给我点思路”（owner 决定，2026-11-16）。** 针对母题陌生、缺少背景知识的学生，追问问不出他不知道的东西。

| 项 | 规定 |
|---|---|
| 在哪里可用 | 卡片，以及完整作文的写前提纲 |
| 可用条件 | 学生在这道题上已经写了自己的一版：立场栏和至少一条理由栏有内容。由代码检查 |
| 条件不满足时 | 按钮不可用。Tutor 按现有阶梯引导学生先写一版 |
| 给什么 | 2～3 条切入视角或反方考量，每条一句话，和学生已写的理由不同 |
| 不给什么 | 展开的因果链、例子、可以直接抄进作文的英文句子、整段文字 |
| 怎么呈现 | 一张对照卡片，没有“放进卡片”按钮。学生想用某个视角，要自己在栏里写出理由和为什么 |
| 触发方式 | 每次单独点击，不保留为模式。不限次数，靠用量计费自然约束（owner 决定）。再次触发时不重复已经给过的视角 |
| 怎么记录 | 记一条帮助事件，入口为 `card_ideas`（卡片）或 `outline_ideas`（提纲），级别高于 A2。此后这张卡片上修改过的栏标记为“参考后写的” |
| 记录的后果 | 标记的栏不进入个人素材唤醒（§5.5）；用这张卡写成的作文，论证技能不算独立证据 |
| 不可用的场合 | 模考；用于新题检验的练习 |

- 这不是“再给点提示”的下一级。点“再给点提示”仍然只到 A2。
- 这是对 G1 和 agent_tutor §10.3 第 5 条的有限放宽：学生可以得到内容，但必须先自己尝试，并且得到的内容被如实记录。
- 这个动作是单独的调用，用自己的系统规则，不带 G1～G6。教练的系统规则禁止给话题角度并且优先于任务指令，放在同一次请求里会互相矛盾。教练的其他调用不变，也看不到参考视角给过什么：学生想讨论某个角度时，要用自己的话说出来。
- 行为评测集要加入的用例：没写就请求；给出的视角越界成因果链或例子；同一道题连续触发多次时，视角有没有重复，有没有逐步拼成完整的论证；学生要求直接填进卡片。

**连续失败时** 按 user_workflow_v2 §7.5 处理：换一种帮助方式，不自动升级；仍然卡住时直接讲一次这个目标要求什么。

## 6. 记忆工作空间

### 6.1 结构

记忆存在 SQLite 里，按 `userId` 隔离，不用磁盘上的 Markdown 文件。对 Tutor 暴露为几个只读视图：

| 视图 | 内容 | 谁写 | 阶段 |
|---|---|---|---|
| `profile` | 目标分、考期、自估水平、基准分、讲解语言、偏好 | 学生；基准分由代码写 | 1 |
| `scratchpad` | 当前练习的教学线程状态和帮助事件 | 代码校验后写入 | 1（已实现） |
| `vault` | 卡片、采用的表达、被指出的句子 | 学生的练习；每条带来源 | 1（现有复习的三种来源） |
| `ledger` | 按分类码的能力证据和状态 | 只有代码 | 3 |
| `portrait` | 学习者画像备忘 | 异步整理，代码校验 | 候选 |

### 6.2 能力账本

- 每次批改完成、核验完成、模考交卷，代码写入一条证据事件；状态由纯函数从剩余证据重新计算，不存增量状态。学生删除某条证据后，下次读取自动重算。
- 状态条件见 §2.4。成果等级见 §2.3。
- 账本只接受评分和核验产生的证据。闪卡自评、点击、用时不进入账本。
- 前置条件：分类表 v2 校准通过。

### 6.3 学习者画像（候选）

v1.0 的设计保留在这里，作为以后采用时的起点：仅在一次练习结算时异步整理；最多 8 条，每条不超过 120 字，注入预算不超过 600 token；每条必须绑定真实存在的来源；学生可以看到、修改、删除。

采用前要补上的约束：

- 原句匹配只能证明学生说过这句话，不能证明归纳成立。“习惯”一类的结论需要来自至少 2 次不同练习的来源。
- 对学生显示为“教练的观察，可以纠正”，不显示为事实。
- 先在行为评测里证明注入画像确实改变了教练的行为，否则它只增加成本。

### 6.4 透明与删除

- 学生可以看到教练依据的每条记忆和它的来源，可以纠正或删除。现有“常见问题”的移除与恢复保留。
- 删除一条记忆或一篇练习后，每次组装上下文和保存晚到结果之前都要过滤掉它（agent_tutor §8.4）。

## 8. 模块规格

### 8.1 完整作文

**不变的部分：** 写前提纲可以跳过；写作时有划词工具和可关闭的提醒（每篇有效提醒最多 2 次）；提交后由隔离的评分调用给出总分、四项分和按影响排序的最多 3 个问题，定位到原句。

**改动：完成点是“改好一个问题”（owner 决定）。**

1. 报告最上面是总分和四项分，这是现状（owner 决定保留）。分数下面是首要问题：原句、它为什么影响分数、改写方向，以及“改这个问题”。其余问题可以展开查看。“先推进一个问题”是 `TUTOR_V2_ENABLED` 下已有的界面。分数区要足够紧凑，让首要问题和按钮不用滚动就能看到；这一条是我的补充。
2. **修改范围** 由代码根据问题涉及的句子计算（user_workflow_v2 §8.4）：一句就改一句，同段几句就重写这一段，跨段就列出涉及的段落。学生可以扩大范围。
3. 学生提交修改后，**隔离核验** 判断这个问题是否解决，读入题目和全文，不重新给全文打分。目标是几秒内返回。
4. 结果：
   - 解决：练习标为“完成”。记录首次尝试的结果和之前用过的帮助。
   - 部分或没解决：Tutor 按帮助阶梯给一个提示，学生再试。第二次尝试之后的结果记为帮助后的结果。
   - 学生可以随时选“先到这里”。
   - 通过核验之后学生还可以继续改。只要没动核验过的那几句，练习仍是“完成”。动了那几句，练习回到“已反馈”，再核验一次通过才重新算“完成”。之前那次通过的记录保留，它说明学生写出过这个改法。
5. **跳过：** 学生可以不改。练习标为“已反馈”，这个问题在 7 天内出现在“今天”（§3.3 规则 3）。

| 状态 | 含义 | 在进展页 |
|---|---|---|
| 已反馈 | 拿到报告，没有改 | 计入完成的写作数，标明未修改 |
| 完成 | 首要问题核验为解决 | 另外计入“改好的问题” |

- **二稿全文重评** 保留，改为学生主动选择。提交后给出两稿分数和每个问题的解决状态，这是现有的对比。
- 被指出的句子和学生的改法进入复习。错句本现在就是这样工作的。
- user_workflow_v2 §12 第 3 项建议把分数移到第二屏，owner 决定不移。

### 8.2 题目卡片

面向能造句、但对母题陌生或论证停在表面的学生。第一阶段只做 Task 2。

- **结构：** 沿用现有的按题目小问分栏，结构随题型变化。可以用中文、英文或混写。增加一个可选的“本题表达”栏，记 2～4 个想用的英文说法。v1.0 把结构改成了固定的“立场 + 论点链 × 2～3 + 词伙”；owner 已确认沿用按小问分栏，因为它能防止漏答题目的一部分。
- **与 Tutor 的配合：**
  - 接入统一 Tutor，取消“每张卡 2 次追问”的配额。
  - Tutor 关注三件事：是否回应了题目的每个部分和限定词；理由有没有循环论证、跳步或空话；有没有可以展开的具体内容。不纠拼写。
  - 学生在对话里说的话可以整段或选一段放进某一栏。Tutor 不写卡片内容。
  - “给我点思路”按 §5.4。
- **检查：** 学生点“检查”，核验类调用逐个小问判断。“每张卡 2 次检查”的配额也取消（owner 决定）。每张卡的检查次数照常记录，用来观察有没有人靠反复检查试答案。
- **归档：** 通过的卡片进入卡片库和复习，可以随时写成完整作文。没通过的保存为“还需展开”，写明缺什么。

### 8.3 复习

- **来源：** 被指出的句子、采用的表达、通过的卡片。三种来源现在都有。
- **排期：** 间隔 1、3、7、14、30 天，一次最多 12 条。这是现状。
- **方式：** 先自己写，再对照当时的答案，自评“记住了”或“还不稳”。不调用模型，不消耗 credits。自评只影响复习排期。
- **新增：错句可以请求核验。** 学生换了一种改法时，可以点“核验我的改法”。这是核验类调用，判断语法和原意是否成立。结果不改变复习排期。
- **候选：观点卡的变式复习。** 遮住自己的卡片回忆原题的论点，练的是记忆，而考试不会重复这道题。更有价值的形式是给一道同母题的新题，问“你哪张卡的理由能用，要怎么改”。采用条件见 §12.2。
- **提醒：站内提醒加浏览器推送（owner 决定）。**
  - 站内有四处：侧栏“复习”的到期数量；“今天”面板的“先复习”；“今天”里还没改完的问题（§3.3 规则 3）；面板下方的模考邀请。前两处和最后一处是现有功能。
  - 浏览器推送让学生没打开产品时也能收到提醒，处理的是 user_workflow §10 的断点 8。触发条件是当天有到期复习，或有还没改完的问题。同一个学生每天最多一条，沿用 v1.0 给邮件定的上限。
  - 授权请求放在学生完成第一次练习之后，不放在注册时；账户设置里可以随时关闭。这一条是我的补充。
  - 覆盖面有限：微信内置浏览器不支持；iPhone 上需要先把网站添加到主屏幕。不支持的环境不显示授权请求。Chrome 和多数安卓浏览器的推送经过 Google 的服务，在中国大陆通常连不上，实际覆盖要在试用里用学生自己的设备确认。
  - 推送不带内容，通知文字是固定的。服务器只向已知推送服务的地址发请求。
- **候选：邮件等其他站外渠道。** v1.0 设计了每天最多一封的汇总邮件，采用条件见 §12.2。

### 8.4 进展

- **第一阶段：** 现有内容保留，即模考趋势、练习分数（注明有教练帮助）、常见问题。增加“改好的问题”列表，每条显示首次尝试的结果和用过的帮助。
- **阶段 3：** 按技能显示三种成果（§2.3）；账本状态和原句证据；记忆的查看、纠正和删除。
- **候选：** 题型与母题的覆盖矩阵；Tutor 在进展页的诊断与跳转。

### 8.5 模考

- **第一阶段：** 现有的 Task 2 独立模考，40 分钟，题目从学生没见过的保留题里抽，开始前确认没在别处练过，没有教练，计时按服务器时间。作为注册赠送的基准（§3.4）。
- **净题与其他模考分开显示。** 只有按时提交、没用过教练、开始时符合条件的模考进入成绩趋势。这是现状，保留。
- **阶段 2：** Task 1 + Task 2 的 60 分钟联考，两题之间可以切换，按 `Task 1 × 1/3 + Task 2 × 2/3` 取最近的 0.5 分；考后报告包括两题的用时分配。输入时间线只显示输入发生在什么时候，不推断学生在构思还是检查（user_workflow_v2 §9.5）。
- **取消 14 天冷却（owner 决定）。** 只要还有学生没见过的保留题，他可以随时从模考页开始一次净题模考。首页的模考邀请最多每 7 天出现一次（owner 决定）。保留题的消耗见 §7.2。
- **候选：** 单项限时模考、自选题模考。

## 9. 计量（owner 决定）

credits 按实际用量消耗，与落地页的档位和用量条一致。配套设计：

- 界面显示用量条和“一篇作文通常用多少”，不给每条消息标价。
- 不调用模型的动作不消耗 credits：闪卡复习、“今天”的推荐、代码拼装的开场。
- 赠送的基准模考不消耗 credits。
- 评分和核验在所有档位下使用同一配置，档位只影响教学调用。评分调用看不到档位。
- 首要问题的核验包含在批改里（owner 决定）：提交批改时一并计入，之后改这个问题不再消耗 credits，多次尝试的核验也一样。期间向 Tutor 要提示属于教学调用，照常计量；其他问题的核验也照常计量。
- 具体的点数和档位价格，等试用测出每类调用的实际成本后再定。

## 11. 指标与验证

**北极星** 沿用 agent_tutor §13：未提示的新题原稿和模考里，重点技能的问题是否减少。试用阶段只做描述，不下结论。

**第一阶段要看的：**

| 指标 | 回答什么 |
|---|---|
| 拿到报告后开始修改的比例，以及核验为解决的比例 | 学生会不会改，改不改得动 |
| 从报告到改好一个问题的用时；选择“先到这里”或跳过的原因 | 这一步是否舒适 |
| “给我点思路”的触发比例和每道题的触发次数；触发后学生是否自己写出了理由 | 先试后给有没有变成默认路径 |
| 浏览器推送的授权比例；收到推送后当天回来的比例 | 推送覆盖了多少人，有没有用 |
| 做完第一次练习后，7 天内回来做第二次、第三次的人数 | 学生会不会回来 |
| 基准模考的接受比例和完成比例 | 40 分钟的首次体验是不是门槛 |
| 每类调用的延迟、token 和重试次数 | 用量计费下一篇练习的实际成本 |

**持续要看的** 见 user_workflow_v2 §11：同等帮助条件下首次尝试做到的比例；隔 3 天以上换题不预告再次做到的比例；练习评价里的负面反馈。

**不能当作学习证据的数字：**

| 数字 | 为什么 |
|---|---|
| 帮助后的通过率 | 给了提示，它自然会涨 |
| 每周反馈次数 | 练习单位变小，它自然会涨 |
| 闪卡自评的“记住了”比例 | 是自评 |
| 求助次数 | 减少入口，它自然会降 |
| 用了参考视角的卡片的通过率 | 内容不全是学生自己的 |

3～5 人的试用只能发现机制问题，不能说明提分有效。

## 14. 风险

| 风险 | 应对 |
|---|---|
| 参考视角成为每张卡的固定步骤，产品变成观点提供者 | 必须先写一版；没有一键填入；用过之后修改的栏如实标记。次数不设上限，所以触发比例和每道题的触发次数是第一阶段的观察指标和停止条件 |
| 模型给的“视角”越界成因果链或例子 | 行为评测用例；拿不准按越界处理（agent_tutor §10.3 第 7 条） |
| 核验把没解决判成解决，学生得到错误的“完成” | 核验隔离；评测集覆盖循环论证、空泛解释等情形（user_workflow_v2 §8.1）；结果显示核验的原因 |
| 改一个问题增加了步骤，学生嫌麻烦而跳过 | 范围取最小；目标几秒内返回；可以跳过并在下次“今天”出现；跳过比例是停止条件 |
| 基准模考 40 分钟，新用户不愿意做 | 可以稍后；没做时用自估水平；接受比例偏低时考虑“贴一篇旧作文”作为更轻的入口 |
| 未校准的基准分被当成真实水平 | 显示为区间并标明 AI 预估；只调整默认值，不锁定功能 |
| 按用量计费让学生不敢提问 | 不给单条消息标价；不调用模型的动作免费；首要问题的核验包含在批改里 |
| 分数在报告最上面，学生看完分数就离开 | 分数区保持紧凑，首要问题和按钮不用滚动就能看到；“开始修改的比例”是观察指标 |
| 自编题与真实考题的风格有差距 | owner 和 astra 编题并审查；允许学生粘贴自己的题 |
| 占位题迟迟没有填完，试用没有题可用 | 阶段 0 以占位题全部填完并通过审查为完成条件 |
| 浏览器推送在微信和 iPhone 上覆盖有限 | 不支持的环境不请求授权；授权比例是观察指标；邮件等渠道留在候选池 |
| 取消冷却后保留题很快用完 | 保留池扩到 20 道；用完后的模考不进入成绩趋势，并向学生说明原因（§7.2） |
| 卡片检查不限次数，学生靠反复检查试答案 | 检查只说明缺什么，不给内容；记录每张卡的检查次数，试用中观察 |
| 手机上三栏布局不可用 | 试用前按 §3.1 核对卡片、复习、今天三个页面 |
| 账本和撤支架在阶段 3 才有，第一阶段的“越用越了解”有限 | 第一阶段只承诺不重复追问和“上次也出现过”；对外不宣传记忆能力 |
| 合规主体未定 | 沿用商业计划备忘录 §9：进入公开试用前取得法律意见 |
