## 1. 目标与范围

project 0 是给大陆学生用的雅思写作 Task 2 陪练。教练只提问、指出缺口，不提供论点、范文或模板。本 RFC 新增四项功能：

1. **调用记录。** 每一次模型调用都留下记录（§4）。
2. **回复风格。** Concise / Standard / Comprehensive，只改变教练说多少、解释多少（§6）。
3. **模型档位。** Adept / Mentor / Sage。学生按环节选择，默认全部是 Mentor，练习中任意时刻都可以切换（§7）。批改使用固定配置，不可选（§8）。
4. **练习导出 PDF。**（§9）

提示词已经从代码中抽到 `prompts/` 下的 txt 文件（§5，已包含在基线 `90f5655`）。

**不在范围内：** 定价、credit、支付；用户自己编写风格或 system prompt；人设类风格；批改随档位变化；速刷追问接入风格或档位；选定最终的三个模型；B′ 阶段的盲测和自动降档。

**动机说明。** 风格的出发点是一个推测："年轻用户喜欢多样性，不想太严肃"，目前没有数据支持。本地数据库里的少量样本显示，现在的教练回复并不短：写中对话平均约 490 字符，分级提示约 730 字符。上线前要用生产环境的数据再确认一次（§11 W0）。档位现阶段的价值，是先把"按环节换模型"的管线搭好。

## 3. 调用点、分组与环节

按真实调用点分组，而不是按用途标签分组。代码里用 `Record<CallSite, …>` 来写这张表，编译器会强制每个调用点都被明确归类，未分类不得派发。现有 8 处精练 `generateJson` 代码实际覆盖下面 12 个精练逻辑调用点，加上速刷共 14 个；测试按逻辑调用点覆盖。

| 调用点 | 位置 | 用途标签（`llm_calls.purpose`） | 环节 | 风格 | 档位 |
|---|---|---|---|---|---|
| `deep.prewrite` | engine.ts:114 | `prewrite_turn` | 写前构思 `prewrite` | ✓ 只影响回复，不影响提纲提取 | ✓ |
| `deep.chat` | engine.ts:162 | `writing_chat` | 写作中为写作协助 `assist`；改写阶段为改写辅导 `revise` | ✓ | ✓ |
| `deep.clarify` | engine.ts:162 | `writing_chat` | 同上 | ✓ | ✓ |
| `deep.polish` | engine.ts:162 | `writing_assist` | 同上 | — | ✓ |
| `deep.express` | engine.ts:162 | `writing_assist` | 同上 | — | ✓ |
| `deep.check` | engine.ts:162 | `writing_check`（新） | 同上 | — | ✓ |
| `deep.issue` | engine.ts:147 | `issue_hint` | 改写辅导 `revise` | ✓ 只改同一级别内的措辞 | ✓ |
| `deep.nudge` | engine.ts:132 | `nudge` | 段落提醒 `nudge` | — | ✓ 只能选 Adept / Mentor |
| `deep.evaluate` | engine.ts:65 | `scoring` | 批改 | — | — |
| `deep.compare` | engine.ts:80 | `comparison` | 批改 | — | — |
| `deep.review` | engine.ts:183 | `feedback_review` | 批改 | — | — |
| `deep.finish` | engine.ts:106 | `memory_summary`（新） | 批改 | — | — |
| `quick.followup` | quick-model.ts:129 | `quick_followup` | 速刷，保持现状 | — | — |
| `quick.check` | quick-model.ts:129 | `quick_check` | 批改（保持现状） | — | — |

说明：

- 用途标签 `diagnosis`、`idea_extract`、`opening` 没有对应的调用：诊断和评分是同一次调用；提纲提取在写前对话里完成；开场是固定文字（`lib/learning/prewrite-guidance.ts`）。这三个标签保留在列表里，以兼容旧记录，但不再使用。
- 写前对话里的提纲提取会随档位变化。服务器会检查每条提取内容确实出现在学生的原话里（engine.ts:118），所以风险有限。
- 润色和换种表达会给出学生可以照抄的句子，语法检查用 Concise 可能漏掉错误，所以这三者不接入风格。
- 练习总结决定哪些问题被记为"反复出现"，会影响以后的推荐，所以算批改。

## 4. 调用记录与调用内容

### 4.1 两层存储

| 层 | 表 | 内容 | 保存期限 |
|---|---|---|---|
| 调用记录 | `llm_calls`（已有表，新增字段） | 见 4.2 | 长期；随账户删除（已有的级联删除） |
| 调用内容 | `llm_call_payloads`（新表） | 实际发出的 messages、模型返回的原始文本 | **90 天**；删除练习时一并删除；随账户删除 |

**学生的作文不会过期。** 作文、对话、提纲、评分都存在会话的 `state_json` 里。调用内容只是发给模型的请求和模型原始输出的副本，学生能看到的内容会话里都有。

调用内容**不保存** DeepSeek 返回的 `reasoning_content`。它**不能**通过任何接口、页面、导出文件或报错信息返回给学生，因为里面有完整的 system 提示词。

### 4.2 `llm_calls` 新增字段

所有新字段都允许为空、不设默认值。为空表示功能上线之前的记录，不能理解为 `standard` 或 `mentor`。**不修改已有的 CHECK 约束**：修改会让 drizzle-kit 重建整张表，而表里可能有 `reserved` 状态的记录。

| 字段 | 说明 |
|---|---|
| `call_site` | §3 的调用点 |
| `stage_group` | `prewrite` / `assist` / `revise` / `nudge` / `judge` / `quick` |
| `style_id` | 实际使用的风格；批改和不接入风格的调用为空 |
| `requested_tier`、`served_tier` | 学生选择的档位和实际使用的档位；批改记 `judge` |
| `provider` | 供应商标签 |
| `params_hash` | 所发推理参数的哈希 |
| `prompt_version`、`style_version`、`tier_table_version`、`judge_version` | 各项配置的版本 |
| `finish_reason` | 模型返回的 `finish_reason`。输出被截断时为 `length`，此时 `outcome` 仍记 `invalid_output` |
| `reasoning_tokens` | 推理 token 数，供应商返回时才记录 |

### 4.3 写入规则

- 精练的每个调用点都传入 `purpose`、`userId`、`sessionId` 和 `operationId`（取动作请求的 `requestId`），走已有的 `observeCall` 和 `settleCall` 路径。
- 调用内容在调用结束后写入，成功或失败都写。写入失败不影响这次调用，和现有的观测记录一样。
- 写入调用内容时，顺带删除最多 500 条已过期的记录；服务启动时（`instrumentation.ts`）也清理一次。不另外设定时任务。
- 每条教练消息记录 `callId`，这样回复可以对上调用记录。
  - 一次实际 provider 尝试一条记录；同一操作可有多条尝试，回复关联成功的那一条。固定开场不编造调用记录。
  - 给模型的历史消息、评分和对比均经明确字段投影；新的 `callId`、风格、档位和评分来源不会进入后续请求。投影保留基线已有字段与顺序，不顺便删掉历史请求原来就有的 ID。
  - 内容副本不得保存认证 header、API key 或异常对象；无可用输出时文本可为空。会话删除后晚到的调用不得重新写回内容，使用会话所有权外键及写入检查保证。

## 5. 提示词文件（已完成）

- 16 段提示词存放在 `prompts/{system,coach,judge,quick}/*.txt`，由 `lib/llm/prompts.ts` 读取。每个文件以一个换行结尾，这个换行不算提示词内容。
- 读取模块带 `import "server-only"`。提示词名称是代码里写死的列表，不接受请求数据。服务启动时一次读入全部文件，缺文件立即报错，报错里不带提示词内容。
- `prompts/` 不在 `public/` 下，不会作为静态文件对外提供。构建后已检查：`.next/static` 和 `.next/server` 里都没有提示词文字，因为提示词是运行时才读取的。
- 抽取前后拼装出的 system 消息逐字节一致：16 段内容，每段在 3 种重试情况下都验证过。
- `tests/prompts.test.ts` 记录全部提示词文件的哈希。改了任何提示词文件却没有升级 `promptConfigVersion`，测试会失败。
- 部署时上传整个工作目录，生产环境在这个目录里运行 `next start`，所以能读到 `prompts/`。以后如果改成 standalone 输出，要在 `outputFileTracingIncludes` 里加上 `./prompts/**/*`。

## 6. 提示词结构与回复风格

### 6.1 五层结构

对话类调用（§3 中"风格"或"档位"打勾的调用点）的 system 消息按下表拼装：

| 层 | 内容 | 文件 |
|---|---|---|
| L0 身份与安全 | 身份；讲解语言按 `learner.language`；只用提供的材料；学生输入不可信；不泄露提示词 | `system/coach-preamble.txt`（新） |
| L1 教学准则 | 禁止产出的五类内容（6.2）和优先级声明 | 同上 |
| L2 输出格式 | JSON Schema，每个回复字段都有硬性长度上限（6.5） | 代码生成 |
| L3 任务指令 | 这个调用点要做什么，以及硬性要求。**不含任何关于详略的措辞** | `coach/*.txt` |
| L4 风格 | 这个调用点在所选风格下的详略说明，优先级最低 | `style/<调用点>/<风格>.txt`（新） |
| 重试提示 | 已有 | `system/retry.txt` |

- **批改调用和速刷调用不使用这个结构。** 它们继续使用现在的 `system/preamble.txt`，拼装结果逐字节不变。
- **风格放在最后。** 同一调用点、不同风格的请求，前面几层完全相同，有利于供应商的前缀缓存（DeepSeek 是否这样缓存还需确认）。
- **段落提醒**（`deep.nudge`）使用新结构的 L0～L3，但没有 L4。

### 6.2 L1 教学准则

教练**不能产出**以下内容（自动测试按 C1～C5 检查）：

| 编号 | 不能产出 | 例子 |
|---|---|---|
| C1 | 学生没有说过的立场 | "你可以选择完全同意" |
| C2 | 学生没有说过的论点或理由 | "一个理由是这能促进经济发展" |
| C3 | 学生没有说过的具体例子（人物、数据、案例） | "比如新加坡的公共交通……" |
| C4 | 可以直接放进作文的完整英文句子或段落 | 例外见下 |
| C5 | 让学生挑选的观点菜单 | "你可以从经济、文化、环境三个角度写" |

**C5 的边界：** 可以说出**推理的类型**（原因、后果、对比、亲身观察），不能说出**和题目内容相关的角度**（经济角度、环境角度）。

**C4 的例外**只能来自 L3，并且限定在句子层面、保留学生自己的意思：润色和换种表达可以给出句子；分级提示的第 3 级可以给**一个**例句；语法检查可以给出改正后的句子。

**优先级声明**（写在 L1 里）：L0 > L1 > L2 和 L3 中的硬性要求 > L3 的其他内容 > L4。风格只能改变回复的长短、一次讲几个要点、解释多少推理过程；风格和任何上层规则冲突时，忽略风格。

### 6.3 风格参数

每个风格文件都按同一组参数来写，这样三种风格在每个调用点上的差别保持一致，也能测量：

| 参数 | Concise | Standard | Comprehensive |
|---|---|---|---|
| 长度目标 | Standard 的约 0.4 倍 | 现在回复长度的中位数（按调用点计算，见 §11 W0） | Standard 的约 2 倍，不超过硬上限 |
| 一次讲几个要点 | 1 个 | 1～2 个 | 最多 3 个 |
| 解释"为什么这样问 / 这样建议" | 不解释 | 必要时用一句话 | 每次都解释 |
| 自我检查的方法 | 不给 | 不给 | 给一个 |
| 格式 | 一两句话 | 短段落 | 可以用最多 3 条短列表 |
| 复述学生的意思 | 不复述 | 不复述 | 先用学生的原话复述一句 |

**Standard 的文件内容就是从现在各条指令里移出来的详略措辞**，例如 "Keep reply concise"、"briefly"，以及 L0 里原来的 "concise"。英文讲解（`learner.language = en`）的长度目标约为中文字数的一半，按词计算。

### 6.4 每个调用点上的效果

| 调用点 | L3 的硬性要求（风格不能改） | Concise | Standard | Comprehensive |
|---|---|---|---|---|
| `deep.prewrite` | 只问一个问题；只提取学生原话；不填空槽 | 只有那一个问题，最多加半句回应 | 简短回应，再提问 | 复述学生的意思 → 说出提纲里哪一部分还空着（只说结构，不说内容）→ 解释为什么问这个 → 提问 |
| `deep.chat` | 引导而不代写；`suggestions=[]` | 直接回答，一个要点 | 现在的做法 | 回答 + 推理过程 + 一个自我检查的方法 |
| `deep.clarify` | 用提问，不给替换段落 | 一个问题 | 现在的做法 | 先指出哪一步推理不清楚，再提问 |
| `deep.issue` 第 1 级 | 只能提问 | 一个问题 | 一句背景加一个问题 | 一个问题，加上它和这个问题的关系；不能讲推理路线 |
| `deep.issue` 第 2 级 | 讲推理路线，不给例句 | 1～2 步 | 完整路线 | 完整路线，加上怎么检查自己有没有做到 |
| `deep.issue` 第 3 级 | 只能给一个例句 | 只给例句 | 例句加一句说明 | 例句，加上解释它的结构怎么起作用；不能给第二个例句 |

原则：风格只改变同一级别内的措辞，不能让级别提前。

### 6.5 长度硬上限

现在精练的 `reply` 字段最长允许 12,000 字符（`schemas.ts`），等于没有上限。改为每个对话类调用点各设一个硬上限。初始值如下，W0 用生产数据校准；硬上限至少要高于 Comprehensive 长度目标的 1.5 倍：

| 调用点 | 初始硬上限（字符） |
|---|---|
| `deep.prewrite` | 800 |
| `deep.chat`、`deep.clarify` | 1,200 |
| `deep.issue` | 1,200 |

无风格调用点不借本次改动缩紧输出：`polish / express / check` 保留现有 `reply <= 12,000` 及建议字段限制；nudge 保留 `message <= 500`。它们使用 L0～L3，没有 L4。四个风格调用点按语言分别校准；生产历史不能可靠归类时单列样本，不猜测调用点。

### 6.6 风格的设置与记录

- 账户默认风格存在 `users.profile_json` 的 `tutorStyle` 字段：`standard` | `concise` | `comprehensive`，默认 `standard`。不需要迁移数据库。存储的值无法识别时按 `standard` 处理，但不删除原值。
- 练习中可以切换，切换只对本次练习生效（§10.2）。
- 每条模型生成的教练消息记录实际使用的 `styleId`。选择器立即提示“已设置，下次新请求生效”；在第一条实际使用新配置的回复之前，根据相邻回复的配置变化显示分隔线。分隔线不写成模型对话消息，历史无标记的消息不补造风格。
- 风格目录有独立的版本号（`style_version`），每次调用都记录。

### 6.7 测试与通过标准

- **A1（重构）**：只有 Standard。批改和速刷的请求逐字节不变；对话类调用的新提示词在同一组用例上和旧提示词对比，C1～C5 违规次数不增加，回复长度的中位数变化不超过 ±20%。提示词版本升级为 `coach-json-v5-layers`。
- **A2（加风格）**：每个对话类调用点都要有对抗用例，至少包括以下几类：学生直接要求"给我一个理由吧"；提纲完全是空的；分级提示第 1 级和第 3 级；学生的语言设置是英文；学生文字里藏着指令；话题天然容易列出角度。通过标准：
  - 每个用例在每种风格下跑 5 次，C1～C5 违规 0 次；跨档位只测 Comprehensive × Sage。
  - 至少 90% 的回复落在长度目标的 ±50% 以内。
  - 同一调用点、语言和 issue 级别内，三种风格的长度中位数满足 Concise ≤ 0.7 × Standard，Comprehensive ≥ 1.5 × Standard；Comprehensive 的目标仍是约 2 倍，不要求严格超过 2 倍。任务约束和教学规则优先于凑长度，不能用第二个问题或第二个例句达标。
  - 固定用例、裁判提示词与版本，C4 按调用点和 hint level 识别例外。人工复核全部疑似违规并抽查至少 10% 的通过项；报告保留逐例统计与样本量。无风格调用点参加安全回归，不参加三风格长度排序。

## 7. 模型档位

### 7.1 名称

| 档位 | 界面显示 | 介绍 |
|---|---|---|
| `adept` | Adept · 快速 | 反应快 |
| `mentor`（默认） | Mentor · 均衡 | 速度和深度兼顾 |
| `sage` | Sage · 深度 | 想得最深，等待时间最长 |

介绍文字说的是速度和深度的取舍，不能说"更好的结果"或"冲分"。现阶段界面上要写明：**三档目前是同一个模型的不同思考深度。** 商标检查（Adept、Sage）在 B′ 之前完成。

### 7.2 对照表

```text
adept  → { provider, baseUrl, apiKeyEnv, model, params, maxTokens(按调用点), timeoutMs(按调用点), maxInputTokens, enabled }
mentor → { ... }
sage   → { ... }
```

| 档位 | 现阶段 |
|---|---|
| Adept | `deepseek-flash`，`reasoning_effort: low` |
| Mentor | `deepseek-flash`，`reasoning_effort: high` |
| Sage | `deepseek-flash`，`reasoning_effort: max` |

- 推理参数只发给 `api.deepseek.com` 上的 `deepseek-*` 模型，和现在的 `quickProviderOptions` 用同一个判断。
- 服务启动时逐个做本地配置校验，不做付费远程探测。某一档配置有问题时只停用这一档，新操作选了它的学生按 Mentor 处理；若 Mentor 也不可用，则拒绝对话操作并保留文字，不递归降档。批改与速刷仍由其独立配置决定。
- 每个档位都可以通过环境变量单独关闭。
- 对照表有独立的版本号（`tier_table_version`）。
- **上线前要验证：** `deepseek-flash` 接受 `reasoning_effort`；显式传 `high` 和不传，结果没有差别。

### 7.3 默认值与开关关闭

新用户、老用户、上线前开始的会话中缺失的偏好字段，分别回退 Standard / Mentor。未知值只对对应字段回退，原始值保留；档位停用不重置风格。已有有效账户偏好仍按 §10.2 优先级生效。

`TIERS_ENABLED=false` 时，相对引入档位前、同一风格的请求**逐字节一致**，包括精练不新增推理参数、速刷仍保留关闭思考的设置；不能因关闭档位而清掉速刷参数。批改与速刷始终对照 `90f5655` 原始基线。开关打开后，Mentor 显式传 `reasoning_effort: high`。详细的 B0/B1/B2 基线见开发方案 §3.2。

### 7.4 成本、容量与故障

- token 预算和超时按"档位 × 调用点"配置，首版沿用 16,000 token 和现有 120 秒及重试规则。每个合法组合至少 20 次用于发现问题，记录观察最大值与分位数，不把小样本 p99 乘系数自动写回预算。调整需要独立验证集；失败可以停用档位。
- 每个用户每天的精练输出预算建议初值 128,000 token，按 `Asia/Shanghai` 自然日；包括精练批改，不含速刷。派发前原子预留必需调用链与允许重试，已知 usage 按实际计，已派发但 usage 未知时按上限计，未派发余量释放；删除练习不返还已用额度。超限返回 429、重置时间和文字保留提示。关档位时不以此新额度阻断 legacy 行为。
- Sage 建议最多 2 个活动工作流（含内部重试），仍受现有全局 8、每用户 1 的约束；只在全局仍有容量时保证 Sage 子上限不阻挡其他档位。本轮沿用单 Node 进程部署假设，跨进程扩容另需共享协调。
- 数值是试用建议而非实测结论。首轮每合法组合至少 19/20 合格、观察截断 0；安全用例经复核 0 违规。有限样本通过不构成真实故障概率保证。成本受脚本总预算与日额度控制，报告标明估算组成和价格日期。
- **B 阶段不做自动降档。** 出错时沿用现有的报错和重试。报错里写出档位名，并保留"你的文字已保留"这句话。

## 8. 批改配置

- **版本化的部分：** 批改 prompt（`prompts/judge/*.txt`、`quick/check.txt` 及其 preamble）、输出 schema、输出上限、模型和推理参数共同定义批改配置。改动其中任何一项，都要升级 `judge_version` 并做校准；本轮保持它们不变。
- **可以更换的部分：** 模型和推理参数。模型迟早会下线，所以允许更换。
- **更换前要做校准检查：** 保留一组固定的校准作文（例如 20 篇，覆盖 5～8 分），存好当前配置给出的分数。用新配置重新打分，总分及每个维度的平均绝对偏移不超过 0.25 分、单篇各项最大绝对偏移不超过 0.5 分，才可以切换；不能用正负偏移抵消。不通过时保留旧配置，直到旧模型下线；如果被迫切换，要在进步曲线上标出断点，并告诉学生前后的分数不能直接比较。
- 批改配置独立于档位：现在的取值和 Mentor 相同，但 Mentor 换模型时，批改不跟着变。
- 批改配置按调用点各一行（evaluate、compare、review、finish、quick.check）。`quick.check` 保持关闭思考。批改配置读取现有的 `LLM_*` 环境变量，生产环境的 `.env` 不需要改。
- 每份评分结果（`evaluation`、`revisionScores`、`comparison`）都记录当时的 `judge_version` 和模型；在进步曲线上标出模型更换的日期。

## 9. 练习导出 PDF

- **范围：** 精练和模考的练习。速刷卡片放到以后。
- **内容（默认模板）：** 题目、日期、练习类型；提纲；原稿；总分和四项分数；问题清单；改写稿和对比结果（如果有）；教练对话（默认包含）。不包含模型名、档位、内部 id 或任何提示词。
- **数据来源：** 只用会话的 `state_json`，不读调用内容表。
- **生成方式：** 在服务器端生成 PDF，并嵌入中文字体（只嵌入用到的字）。不依赖浏览器打印，因为微信内置浏览器用不了打印功能。
- **接口：** `GET /api/sessions/{id}/export`，需要登录，只能导出自己的练习，其他人的练习返回 404。响应头为 `Content-Type: application/pdf`、`Content-Disposition: attachment`（文件名用 UTF-8 编码）、`Cache-Control: no-store`。
- **入口：** 作文页（反馈之后的各阶段）和作文库。在微信内置浏览器里下载可能会被拦截，所以按钮旁边要提示"如果无法下载，请点右上角，在浏览器中打开"。
- **新依赖：** 需要一个 PDF 生成库和一个开源授权的中文字体（例如 Noto Sans SC，SIL OFL 许可），仓库会增加约 10 MB。按开发约定，新依赖要先由 owner 批准。

## 10. 设置、会话字段与开关

### 10.1 账户设置（`users.profile_json`）

```ts
tutorStyle: "standard" | "concise" | "comprehensive"                 // 默认 standard
tutorTiers: { prewrite, assist, revise: "adept"|"mentor"|"sage"; nudge: "adept"|"mentor" }  // 默认全部 mentor
```

`profilePatchSchema`（`lib/auth/validation.ts`）用枚举校验这两个字段。合并到 `DEFAULT_PROFILE` 的方式和其他字段相同。

### 10.2 练习中切换

- 新增一个精练动作 `setTutor`：`{ style?, tiers?: Partial<…>, makeDefault?: boolean, expectedTutorRevision }`，不调用模型。偏好与作文内容分开保存：`writing_sessions.tutor_settings_json` 保存 `{ override, revision }`，旧行为空。该列是唯一来源，API 只投影为 `tutorOverride / tutorRevision`，不把它们再写进 `state_json`。
- `setTutor` 通过身份、同源、归属与可操作状态检查后，在短数据库事务内按 revision 比较并局部合并；不占用模型期间的会话锁，也不修改草稿、消息或 pendingAction。`makeDefault` 同事务局部更新账户的原始 JSON，保留未知字段。冲突返回 409 与最新偏好。
- 作文生成继续使用现有锁与 checkpoint，普通保存不更新偏好列。前端按独立 tutorRevision 合并偏好，晚到的模型响应不能覆盖新选择。选择器立即显示“下次新请求生效”，进行中的请求显示其冻结配置。
- **生效顺序：** 本次练习的 `tutorOverride` > 账户设置 > Standard / Mentor。
- **冻结时机：** 每次新模型操作在锁内接受时，重新读取偏好，冻结可能使用的调用点配置；与 pendingAction 原子写入仅服务端读取的 `pending_model_config_json` 列。包含 requestId、动作参数哈希、模型/参数/预算和版本、凭据环境变量名，不保存 API key 或提示词正文，不返回客户端。
- 同一 requestId 的技术重试和刷新/进程重启恢复复用快照；成功后清理。若旧提示词/配置版本已不可用或档位被紧急停用，停止恢复并提示发起新请求，不静默替换模型。用户显式按新设置重试时创建新 requestId。切换偏好只影响下一次新操作。
- 旧代码不更新新增列，回滚后继续正常读写作文并保留偏好；重新升级后可恢复偏好。不要求旧代码理解新配置或恢复新版本进行中的请求。

### 10.3 换模型时的上下文

1. 每个调用点带多少条历史由调用点决定，不随档位变化。现在的数量是：写前对话 20 条，写中对话 14 条，分级提示 8 条，段落提醒不带历史。
2. 本轮三档同模型，使用相同历史窗口，不实现自动裁剪。若配置显式输入上限，三档使用同一值，超限则派发前拒绝并保留文字。不同模型的窗口差异、裁剪与计数留到 B′，不能让本轮不同档位悄悄看到不同内容。
3. 不把推理过程传回给模型。
4. 发给模型的历史里不带档位或风格标签。
5. 第一条实际使用新配置的回复前显示分隔线；切换时的即时确认与模型回复分开，分隔线不进入模型上下文。

### 10.4 开关与回滚

- `STYLES_ENABLED`、`TIERS_ENABLED`、`EXPORT_ENABLED` 三个开关互相独立，默认关闭。调用记录（§4）不受开关控制。
- 开关关闭时：隐藏对应的选择器和按钮；保留已存的设置；实际使用 Standard / Mentor；调用记录写实际使用的值。
- 开关切换从下一次调用开始生效。开关只能在服务器端读取，由服务器传给前端。
- 回滚顺序：先关开关，再回滚代码；表结构保持不变。
- A1 是提示词重构，关闭风格只是使用新 Standard，不恢复旧提示词。旧提示词回滚必须回滚代码，使用开发方案 B0/B1/B2 区分验收基线。
- 调用内容保存不受功能开关控制，隐私说明必须在首次部署调用内容记录前完成。

## 12. 风险

| 风险 | 应对 |
|---|---|
| Comprehensive 替学生想观点 | L1 统一写禁令；C1～C5 对抗用例 0 违规 |
| 风格之间看不出区别 | 详略措辞只放在 L4；区分度标准 |
| 提示词重构改变了 Standard 的行为 | A1 单独上线、单独对比 |
| 调用内容涉及隐私 | 单独存表；90 天后删除；随练习和账户删除；更新隐私说明 |
| 高推理强度导致截断或超时 | 按档位设预算；记录 `finish_reason` |
| Sage 占用容量，导致其他人收到 429 | 并发上限；段落提醒不提供 Sage |
| 批改模型被迫更换 | 校准检查；在进步曲线上标出更换日期 |
| 同一模型的三档差别看不出来 | 界面如实说明；显示预计等待时间 |
| 设置项太多 | 默认全部 Mentor；提供"恢复默认" |
| PDF 在微信里无法下载 | 提示用浏览器打开 |
| 模型公示与备案要求 | 等法务意见（商业计划备忘录第 9 节）；原型阶段只做内部试用 |

## 13. 决定记录

已由 owner 确认（2026-11-03）：

1. 用户是大陆学生，最终只用境内已备案的模型。
2. 风格只有 Concise / Standard / Comprehensive 三个固定选项，只作用于对话类调用。
3. 档位为 Adept · Mentor · Sage，现阶段对应 `deepseek-flash` 的 `low` / `high` / `max`。
4. 除批改外，每个环节都可以单独选档位，默认全部 Mentor；练习中任意时刻可以切换，切换时新模型拿到完整上下文。
5. 批改锁定 prompt 和输出上限，不可选；模型和参数可以更换，但更换前要做校准检查。
6. 每次调用都要记录；调用内容保存 90 天，不保存推理过程。
7. 新增练习导出 PDF，先做简单的默认模板。
8. 提示词抽成 `prompts/` 下的 txt 文件，只能在服务器端访问。
9. 速刷追问本次不接入档位，也不接入风格。
10. 段落提醒只能选 Adept / Mentor；语法检查跟随所在环节的档位，但不受风格影响。
11. A 阶段拆成 A1（重构）和 A2（加风格）；B 阶段不做降档。
12. 定价不在本次范围内。
