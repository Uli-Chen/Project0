# MVP-1 开发任务台账

更新：2026-10-23。本文件是任务状态唯一来源。当前没有产品功能完成。文档搭建不计作以下开发任务的实现。

“执行／审批”列写主要执行角色与审批人，角色代号定义见 [团队与组织](../organization.md)。所有任务的审批人都是创始人；实现完成后由 AG-REV 评审、AG-QA 或 AG-EVAL 在另一会话验证，不在此列重复。依赖是任务编号，不代表必须由不同 Agent 完成。具体行为以 [模块规格](../specs/README.md) 为准，测试结果以 [验收台账](../validation/acceptance.md) 为准。

先开始 MVP-001、MVP-002；其余任务满足 [就绪条件](../workflow.md#就绪条件) 后由创始人改为 `ready`。在制品上限：`in_progress` 不超过 2 个。

## 任务卡

### MVP-001 — 工程骨架、邀请身份与契约落地

- 需求：FLOW-001、CORE-003。
- 输入：[总览](../overview.md)、[契约](../specs/contracts.md)。
- 交付：前后端本地启动、数据库迁移框架、邀请会话、同意记录、环境变量样例、健康检查；固定依赖版本与任务库选择，记录选择理由。
- 验收：AC-001、AC-014 中身份与角色部分；不得将后续完整安全验收提前标通过。
- 完成定义：新环境按说明能启动，两个测试用户隔离，会话失效行为明确；真实密钥不入库。

### MVP-002 — 题库、Rubric 与评分数据协议

- 需求：SCOR-001、SCOR-004。
- 输入：[评分规格](../specs/scoring.md)、[评测协议](../validation/scoring-benchmark.md)。
- 交付：至少 3 道来源明确的 Task 2 题目；量表聚合与舍入、错误分类、标注手册、双评流程；专家样本获取计划、分组与划分清单。
- 验收：AC-006、AC-008 的数据与契约部分；没有实际专家结果时保留质量验收 not_run。
- 完成定义：至少 2 名签约评分专家审核量表与样例，数据划分可复现；合成样本和真实专家样本有明确标记。

### MVP-003 — 编辑器与草稿恢复

- 需求：FLOW-002。
- 输入：[作答规格](../specs/submission.md)。
- 交付：题目展示、字数、计时、本地与服务端保存、刷新恢复、多标签冲突、存储失败提示。
- 验收：AC-002。
- 完成定义：保存后离线刷新可恢复；冲突不覆盖副本；退出账号清除本机内容。

### MVP-004 — 不可变提交与改写链数据基础

- 需求：FLOW-003、REVI-001、CORE-002。
- 输入：[契约](../specs/contracts.md)。
- 交付：Loop/Draft/Submission/Evaluation 基础表、分句快照、请求幂等、唯一约束、无效输入检查、配额占用的事务边界。
- 验收：AC-003、AC-005、AC-011 的数据约束部分。
- 完成定义：重复请求返回同一资源，键与正文冲突可识别；句子引用绑定不可变内容。

### MVP-005 — 异步任务、阶段恢复与状态读取

- 需求：CORE-001。
- 交付：outbox 投递、Worker 租约、阶段持久化、重试预算、GET 状态、SSE 与断线恢复；可用模型模拟器开发。
- 验收：AC-004。
- 完成定义：在入队前后、阶段结果写入前后模拟崩溃，任务最终可恢复且不覆盖终态。

### MVP-006 — 模型网关、试用额度与用量账本

- 需求：CORE-002、CORE-003。
- 交付：统一结构化调用、超时、有限重试、可追踪 attempt、版本与价格配置、免费闭环额度、并发与频率限制。
- 验收：AC-005、AC-014 的限流部分、AC-017 的成本记录部分。
- 完成定义：失败/超时/重放不重复消耗用户权益；已发生调用成本和 unknown 用量如实记录。

### MVP-007 — 双评、仲裁与结构化结果

- 需求：SCOR-001、SCOR-002。
- 交付：规则特征、两个评分器、仲裁条件、无仲裁聚合、Schema 校验、不可评分分支、配置版本化。
- 验收：AC-006；质量是否达标由 MVP-008 验证。
- 完成定义：相同输入可以追踪完整来源；非法分数与缺失维度拒绝；评分不读取用户画像和原稿分数。

### MVP-008 — 校准、区间开关与离线评测

- 需求：SCOR-003、SCOR-004。
- 交付：校准拟合与推理、隔离数据集、单评与组件对比报告、质量回归脚本、区间覆盖率报告或保持关闭的依据。
- 验收：AC-007、AC-008。
- 完成定义：评测可复现、有独立测试数据；指标未达标时可以记录实现 done，但验证 failed，真实用户试用不得放行。

### MVP-009 — 重点反馈生成与引用校验

- 需求：FEED-001。
- 交付：最多三条候选排序、证据区间检查、首篇不引用历史、反馈失败单独恢复、供评分专家抽检的分层样本集。
- 验收：AC-009。
- 完成定义：无依据不凑三条；句子存在与问题真实分别验证，人工抽检记录问题成立率。

### MVP-010 — 评分、反馈与恢复界面

- 需求：SCOR-003、FEED-001、CORE-001。
- 交付：分数、AI 标识、问题定位、直接改写入口、partial/failed/not_scorable 界面、重试与刷新恢复。
- 验收：AC-004、AC-007、AC-009 的界面部分。
- 完成定义：无校准区间时不展示伪区间；断连后恢复已完成结果；开发模拟模式明确标识。

### MVP-011 — Tutor 级别、局部尝试与额度

- 需求：TUTR-001、CORE-002、CORE-003。
- 交付：L1～L3 服务端状态、局部尝试检查、提示持久化、回复去重、12 次成功回复上限、越级与注入用例。
- 验收：AC-010、AC-005 的 Tutor 幂等部分。
- 完成定义：两次真实未解决尝试才解锁 L3；额度耗尽仍可改写；失败不扣额。

### MVP-012 — 首次改写提交与独立再评分

- 需求：REVI-001。
- 交付：带原稿的改写编辑器、同题同用户校验、首次改写唯一约束、相同文本拒绝、固定 pipeline 再评分。
- 验收：AC-011。
- 完成定义：并发提交只产生一份首次改写；固定版本不可用时阻止未经对齐的比较。

### MVP-013 — 文本对比与问题处理结果

- 需求：REVI-002、REVI-003。
- 交付：词级 diff、句子映射、四种问题状态、同版本分数对比、比较任务独立恢复、对比页。
- 验收：AC-012、AC-013。
- 完成定义：删除句子不显示已掌握；允许分数下降；比较失败不重跑整条评分链。

### MVP-014 — 导出、删除及缓存清理

- 需求：CORE-004、CORE-003。
- 交付：受保护导出、删除任务、tombstone、衍生数据清单、Worker 回写保护、本机清理、备份与恢复操作说明。
- 验收：AC-015。
- 完成定义：删除后无法访问也不能被迟到任务复活，备份恢复演练重放删除记录；未清理完不能虚报完成。

### MVP-015 — 关键事件与闭环漏斗

- 需求：REVI-003、CORE-005。
- 交付：服务端完成确认、事件去重、漏斗查询、匿名数据导出、按 loop_id 汇总质量/耗时/成本。
- 验收：AC-013、AC-016。
- 完成定义：刷新与重放不会重复计算完成；报告明确用户数、闭环数、分母和排除项。

### MVP-016 — 故障、越权与性能验证

- 需求：CORE-001～CORE-005。
- 交付：故障注入、跨用户与跨角色测试、提示注入回归、10 并发闭环下的测量报告、恢复与回滚操作说明。
- 验收：AC-004、AC-005、AC-014、AC-015、AC-017。
- 完成定义：记录实际结果与未解决项；通过不了门槛必须保留 failed，不以“已运行”当“已通过”。

### MVP-017 — 首闭环集成验收与试用发布准备

- 需求：FLOW-001～FLOW-003、SCOR-001～SCOR-004、FEED-001、TUTR-001、REVI-001～REVI-003、CORE-001～CORE-005。
- 交付：端到端录屏/测试、全部 P0 验收证据、固定发布配置、部署与回滚步骤（可由他人按步骤执行）、试用支持时段与告警路径。
- 验收：AC-018 及所有 P0 条目。
- 完成定义：真实用户邀请开关只有在质量、安全、删除、恢复和闭环验收均通过后开启。

### MVP-018 — 小规模试用与下一阶段决策

- 需求：REVI-003、CORE-005。
- 输入：[试用协议](../validation/pilot.md)。
- 交付：约 20 名邀请用户的两周试用记录、漏斗与访谈、错误清单、成本与延迟、继续/调整/暂停扩展的决策记录。
- 验收：AC-019；报告按协议完整记录分母、缺失数据和限制，不能据同篇改写宣布长期提分。
- 完成定义：报告评审完成，后续动作进入新任务；未达到目标如实报告，不把试用成功作为实现 done 的前提。
